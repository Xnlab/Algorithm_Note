# 게임 개발

- **출처**: 이것이 취업을 위한 코딩 테스트다 with 파이썬 (나동빈) — Ch4 구현 실전 문제
- **유형**: 구현 (시뮬레이션)
- **푼 날짜**: 2026-11-02
- **결과**: 오답 (실행 불가 + 논리 오류)

## 문제 요약
바깥이 모두 바다인 N×M 맵에서 캐릭터가 "왼쪽으로 돌기 → 안 가본 육지면 전진, 아니면 다시 돌기 → 네 방향 모두 막히면 바라보는 방향 그대로 한 칸 뒤로, 뒤가 바다면 종료" 규칙을 반복할 때, 방문한 칸의 수를 구한다. 방향은 0 북, 1 동, 2 남, 3 서.

## 떠올렸어야 할 단서
- 규칙이 순서대로 나열되어 있음 → 알고리즘보다 **규칙을 그대로 옮기는 시뮬레이션**
- "왼쪽으로 회전" + 방향 번호가 **북 동 남 서(시계 방향)** 순서 → 왼쪽 회전은 번호 −1
- "네 방향 모두 갈 수 없으면" → **회전 횟수를 세는 변수**가 필요
- "바깥은 항상 바다" → 격자 범위 체크가 필요 없다는 신호

## 내 풀이

```python
n, m = map(int, input().split())
d = [[0] * for _ in range(n)]
x, y, direction = map(int, input().split())
d[x][y] = 1

array = []
for i in range(n):
    array.append(list(map(int, input().split())))

dx = [-1, 0, 1, 0]
dy = [0, -1, 0, 1]

def left():
    global direction
    direction -= -1
    if direction == -1:
        direction = 3

count = 1
turn_time = 0

while True:
    turn_left()
    nx = x + dx[direction]
    ny = y + dy[direction]
    
    if d[nx][ny] == 0 and array[nx][ny] == 0:
        d[nx][ny] = 1
        count += 1
        turn_time = 0
        continue
    else:
        turn_time += 1
    if turn_time == 4:
        nx = x - dx[direction]
        ny = y - dy[direction]
        
        if array[nx][ny] == 0:
            x = nx
            y = ny
        else:
            break
        turn_time = 0

print(count)
```

- 시간복잡도: **O(N × M)** (각 칸은 한 번만 새로 방문하고, 칸마다 회전은 최대 4번)
- 평가: 전체 뼈대(방문 배열, 방향 벡터, 회전 함수, 회전 횟수 `turn_time`, 뒤로 가기는 `x - dx`)는 책 풀이와 같은 방식이다. 다만 아래 버그 때문에 실행되지 않고, 문법만 고쳐도 답이 틀린다.

### 버그 목록

| # | 위치 | 문제 | 결과 | 수정 |
|---|---|---|---|---|
| 1 | `[[0] * for ...]` | 곱할 값 `m`이 빠짐 | `SyntaxError` | `[[0] * m for _ in range(n)]` |
| 2 | `def left()` / `turn_left()` | 정의한 이름과 호출한 이름이 다름 | `NameError` | 둘 다 `turn_left` |
| 3 | `direction -= -1` | 1을 **더함** → 오른쪽으로 회전 | `direction`이 4가 되어 `IndexError` | `direction -= 1` |
| 4 | `dy = [0, -1, 0, 1]` | 1번이 서, 3번이 동이 됨 (문제는 1 동, 3 서) | 입력 방향과 실제 이동 방향이 어긋남 | `dy = [0, 1, 0, -1]` |
| 5 | 전진할 때 | 방문 표시만 하고 **캐릭터를 옮기지 않음** | 같은 자리에서 계속 회전 → 칸 수가 적게 나옴 | `x, y = nx, ny` 추가 |

### 버그별 영향 (직접 실행해서 확인)
- 1·2를 고친 뒤 3·4를 그대로 두면: 책 예제에서 `IndexError`
- 4만 남기면: 책 예제는 우연히 3으로 맞지만, 무작위 맵 19,757개 중 **7,213개 오답** (북→동으로 돌게 되어 사실상 오른쪽 회전)
- 5만 남기면: 책 예제에서 **2** (정답 3), 무작위 맵 중 **13,774개 오답**

## 정답 풀이 (책 풀이 방식)

내 풀이의 버그 1~5만 고친 코드. 구조는 책 풀이와 같다.

```python
# N, M을 공백으로 구분하여 입력받기
n, m = map(int, input().split())

# 방문한 위치를 저장하기 위한 맵 (0: 안 가봄, 1: 가봄)
d = [[0] * m for _ in range(n)]

# 현재 캐릭터의 X 좌표(행), Y 좌표(열), 방향 입력받기
x, y, direction = map(int, input().split())
d[x][y] = 1                         # 시작 칸 방문 처리

# 전체 맵 정보 입력받기 (0: 육지, 1: 바다)
array = []
for i in range(n):
    array.append(list(map(int, input().split())))

# 북, 동, 남, 서 방향 정의 (문제의 방향 번호 0, 1, 2, 3과 같은 순서)
dx = [-1, 0, 1, 0]
dy = [0, 1, 0, -1]

# 왼쪽으로 회전
def turn_left():
    global direction
    direction -= 1
    if direction == -1:
        direction = 3

# 시뮬레이션 시작
count = 1                           # 시작 칸도 방문한 칸
turn_time = 0                       # 현재 칸에서 연속으로 회전한 횟수

while True:
    # 1단계: 왼쪽으로 회전
    turn_left()
    nx = x + dx[direction]
    ny = y + dy[direction]

    # 2단계: 회전한 이후 정면에 가보지 않은 육지가 있으면 전진
    if d[nx][ny] == 0 and array[nx][ny] == 0:
        d[nx][ny] = 1
        x = nx
        y = ny
        count += 1
        turn_time = 0
        continue
    # 정면이 바다이거나 이미 가본 칸이면 회전만 한 것으로 기록
    else:
        turn_time += 1

    # 3단계: 네 방향 모두 갈 수 없는 경우
    if turn_time == 4:
        nx = x - dx[direction]      # 바라보는 방향은 그대로, 한 칸 뒤로
        ny = y - dy[direction]
        # 뒤가 육지라면 이동
        if array[nx][ny] == 0:
            x = nx
            y = ny
        # 뒤가 바다로 막혀 있으면 종료
        else:
            break
        turn_time = 0

# 정답 출력
print(count)
```

## 해설

### 코드의 각 부분이 하는 일

| 코드 | 역할 | 대응하는 지문 |
|---|---|---|
| `d` | 방문 기록. 육지·바다 정보(`array`)와 **따로** 둔다 | "가보지 않은 칸" |
| `dx`, `dy` | 방향 번호 → 한 칸 이동량. 인덱스가 곧 방향 번호 | "0 북, 1 동, 2 남, 3 서" |
| `turn_left()` | 방향 번호를 1 줄인다. 0 → 3으로 보정 | "왼쪽 방향부터" |
| `turn_time` | 이 칸에서 몇 번 연속으로 돌았는지. 4가 되면 네 방향 모두 실패 | "네 방향 모두 이미 가본 칸이거나 바다" |
| `x - dx[direction]` | 방향 벡터를 **빼서** 반대쪽으로 한 칸 | "바라보는 방향을 유지한 채로 한 칸 뒤로" |
| `count` | 방문한 칸 수. 시작 칸 때문에 1부터 | "방문한 칸의 수" |

### 왜 왼쪽 회전이 −1인가
방향 번호가 북(0) → 동(1) → 남(2) → 서(3), 즉 **시계 방향**으로 매겨져 있다. 왼쪽 회전은 반시계 방향이므로 북 → 서 → 남 → 동, 번호로는 0 → 3 → 2 → 1. 그래서 1씩 줄이고, 0에서 줄이면 −1이 되므로 3으로 되돌린다. 이 계산이 맞으려면 `dx`, `dy`의 순서도 반드시 북 동 남 서여야 한다.

### 왜 `turn_time`을 0으로 되돌리는가
- **전진했을 때**: 새 칸에 도착했으니 그 칸에서의 회전 횟수는 처음부터 다시 센다.
- **뒤로 갔을 때**: 마찬가지로 새 위치에서 다시 네 방향을 시도해야 한다.
- 되돌리지 않으면 새 칸에서 한 번만 돌아도 4가 넘어 잘못된 시점에 뒤로 가거나 종료된다.

### 네 번 돌고 나면 방향은?
왼쪽으로 4번 돌면 360°라서 **처음 방향으로 돌아와 있다**. 그래서 `turn_time == 4`인 순간의 `direction`이 곧 "바라보는 방향"이고, 그대로 `dx`, `dy`를 빼면 지문의 "방향을 유지한 채 뒤로"가 된다.

### 뒤로 갈 때는 왜 방문 여부를 안 보는가
지문에서 뒤로 가는 조건은 "뒤가 바다가 아니면"뿐이다. 뒤 칸은 보통 방금 지나온 칸이라 이미 방문한 칸이고, 그래도 이동해야 한다. 그래서 `array`만 확인하고 `d`는 확인하지 않는다. 뒤로 가는 이동은 새 칸이 아니므로 `count`도 늘리지 않는다.

### 왜 범위 체크가 없는가
"맵의 외곽은 항상 바다"라는 조건 덕분에, 캐릭터는 육지 위에만 있고 육지 칸의 상하좌우는 항상 맵 안이다. 이 조건이 없는 문제라면 `0 <= nx < n and 0 <= ny < m` 확인이 꼭 필요하다.

### 책 예제 따라가기

```
1 1 1 1
1 0 0 1      시작 (1,1), 북쪽(0)
1 1 0 1
1 1 1 1
```

| 위치 | 방향 | 회전 후 정면 | 결과 | count | turn_time |
|---|---|---|---|---|---|
| (1,1) | 북 → 서 | (1,0) 바다 | 회전만 | 1 | 1 |
| (1,1) | 서 → 남 | (2,1) 바다 | 회전만 | 1 | 2 |
| (1,1) | 남 → 동 | (1,2) 육지·미방문 | **전진** | 2 | 0 |
| (1,2) | 동 → 북 | (0,2) 바다 | 회전만 | 2 | 1 |
| (1,2) | 북 → 서 | (1,1) 방문함 | 회전만 | 2 | 2 |
| (1,2) | 서 → 남 | (2,2) 육지·미방문 | **전진** | 3 | 0 |
| (2,2) | 남 → 동 → 북 → 서 → 남 | 바다 / 방문함 / 바다 / 바다 | 4번 실패 | 3 | 4 |
| (2,2) | 남 유지 | 뒤 (1,2) 육지 | **뒤로 이동** | 3 | 0 |
| (1,2) | 남 → 동 → 북 → 서 → 남 | 바다 / 바다 / 방문함 / 방문함 | 4번 실패 | 3 | 4 |
| (1,2) | 남 유지 | 뒤 (0,2) 바다 | **종료** | **3** | |

버그 5(이동 누락)가 있으면 3번째 줄에서 (1,2)에 방문 표시만 하고 (1,1)에 머문다. 그 뒤로 (2,2)에 영영 닿지 못해 답이 2가 된다.

## 검증
- 책 예제 (4×4, 시작 (1, 1) 북쪽) → 정답 풀이 `3`
- 3 ≤ N, M ≤ 9, 테두리는 바다인 무작위 맵 19,757개에서 정답 풀이가 규칙을 문장 그대로 옮긴 기준 풀이와 결과 일치

## 배운 점
- 방향이 번호로 주어지면 **방향 배열 순서를 문제 번호에 맞추고**, 회전 방향(시계 +1, 반시계 −1)을 그 순서 기준으로 정한다.
- 시뮬레이션은 "다음 위치 계산 → 조건 확인 → **실제로 이동**"의 세 단계 중 마지막을 자주 빼먹는다. 예제를 표로 2~3단계만 따라가 보면 바로 드러난다.
