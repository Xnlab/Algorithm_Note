- **푼 날짜**: 2026-10-30
- **결과**: 정답

## 문제 요약
N×N 격자의 (1, 1)에서 출발해 L·R·U·D 이동 계획을 차례로 따르되, 격자 밖으로 나가는 이동은 무시할 때 최종 좌표를 구한다.

## 떠올렸어야 할 단서
- "계획서대로 이동", "범위를 벗어나면 무시" → 알고리즘보다 **지시를 그대로 옮기는 시뮬레이션**
- 이동 횟수 ≤ 100 → 한 번 순회 O(K)면 충분
- 좌표가 (행, 열)이라 **U/D가 첫 번째 값, L/R이 두 번째 값**을 바꾼다

## 내 풀이

```python
n = int(input())
x, y = 1, 1
plans = input().split()

dx = [0, 0, -1, 1]
dy = [-1, 1, 0, 0]
move = ['L', 'R', 'U', 'D']

for plan in plans:
    for i in range(len(move)):
        if plan == move[i]:
            nx = x + dx[i]
            ny = y + dy[i]
    
    if nx < 1 or ny < 1 or nx > n or ny > n:
        continue
    
    x, y = nx, ny

print(x, y)
```

- 시간복잡도: **O(K)** (K = 이동 횟수, 방향 4개를 매번 확인하므로 정확히는 4K)
- 평가
  - 정답. 방향 벡터 배열 + 범위 체크 + `continue`로 무시하는 구성이 구현 문제의 정석 틀이다.
  - `x`를 행, `y`를 열로 일관되게 써서 U/D와 L/R의 대응이 정확하다.
  - 주의점: `nx`, `ny`가 안쪽 `for` 안에서만 정해진다. 입력에 L·R·U·D가 아닌 문자가 섞이면 첫 이동에선 `NameError`, 이후엔 **직전 이동의 값이 재사용되는** 버그가 된다. 이 문제는 입력이 보장되지만, 다른 문제에서 같은 패턴을 쓸 때 조심.
  - 방향을 찾은 뒤에도 남은 방향을 계속 비교한다 (`break` 없음).

## 개선된 풀이

```python
import sys
input = sys.stdin.readline

MOVES = {'L': (0, -1), 'R': (0, 1), 'U': (-1, 0), 'D': (1, 0)}

n = int(input())
r, c = 1, 1
for p in input().split():
    dr, dc = MOVES[p]
    nr, nc = r + dr, c + dc
    if 1 <= nr <= n and 1 <= nc <= n:
        r, c = nr, nc

print(r, c)
```

- 시간복잡도: **O(K)** (방향 조회가 딕셔너리라 이동마다 상수 1번)
- 바뀐 점
  - 안쪽 `for` 검색 → **딕셔너리 조회**. 코드가 짧아지고, 잘못된 문자가 오면 바로 `KeyError`로 드러나 stale 값 버그가 생기지 않는다.
  - 범위 체크를 `1 <= nr <= n` 체인 비교로 써서 읽기 쉽게, `continue` 대신 "범위 안이면 이동"으로 뒤집음
  - 변수 이름을 `r, c`로 바꿔 행·열을 헷갈리지 않게 함 (노트 01 README의 규칙)
  - `sys.stdin.readline`으로 빠른 입력 (이 문제에선 차이 없지만 습관화)

## 검증
- 책 예제 `N=5`, `R R R U D D` → 두 풀이 모두 `3 4`
- 1 ≤ N ≤ 8, 이동 1~30개의 무작위 입력 20,000개에서 두 풀이 모두 직접 작성한 if문 기준 풀이와 결과가 일치함을 확인

## 배운 점
- 명령 문자 → 이동량 대응은 **딕셔너리**로 두면 검색 루프와 그 안의 미정의 변수 문제가 함께 사라진다.
- 반복문 안에서만 값이 정해지는 변수를 반복문 밖에서 쓰면, 조건이 한 번도 안 맞을 때 이전 값이 남는다. 기본값을 두거나 구조를 바꾼다.
