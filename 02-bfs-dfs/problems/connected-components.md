# 연결 요소의 개수 구하기 (백준 11724)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — DFS / 백준 11724
- **유형**: DFS (연결 요소 개수)
- **푼 날짜**: 2026-11-27
- **결과**: 오답 (논리는 맞지만 재귀 한도 초과로 `RecursionError`)

## 문제 요약
방향 없는 그래프(노드 N ≤ 1,000, 간선 M ≤ N(N−1)/2)에서 **연결 요소**(서로 이어진 노드 묶음)의 개수를 구한다.

## 떠올렸어야 할 단서
- "서로 이어진 묶음이 몇 개" → **연결 요소** → 아직 안 간 노드에서 DFS/BFS를 시작할 때마다 +1 ([음료수 얼려 먹기](freezing-drinks.md)의 격자 버전과 같은 원리)
- 노드 번호가 1부터, 간선이 "a b" 쌍 → **인접 리스트** `a[노드] = [이웃들]`
- 방향이 없다 → 간선 하나를 **양쪽에** 추가
- N이 1,000 → 노드가 일렬로 이어지면 **재귀 깊이도 1,000** → Python 기본 재귀 한도(1,000)에 걸린다

## 내 풀이

```python
n, m = map(int, input().split())
a = [[] for _ in range(n + 1)]
visited = [False] * (n + 1)

def DFS(v):
    visited[v] = True
    for i in a[v]:
        if not visited[i]:
            DFS(i)

for _ in range(m):
    s, e = map(int, input().split())
    a[s].append(e)
    a[e].append(s)

count = 0

for i in range(1, n + 1):
    if not visited[i]:
        count += 1
        DFS(i)

print(count)
```

- 시간복잡도: **O(N + M)** (노드마다 한 번 방문, 간선마다 양쪽에서 한 번씩 확인)
- 평가
  - **논리는 정확하다.** 책 풀이와 같은 방식이고, 예제 두 개와 노드 15개 이하 무작위 그래프 2,000개 모두 정답.
  - 인접 리스트를 `[[] for _ in range(n + 1)]`로 만든 것, 간선을 양쪽에 추가한 것, 방문 처리를 함수 첫 줄에서 한 것 모두 정확하다.
  - **문제**: 노드 1,000개가 `1-2-3-…-1000`처럼 일렬로 이어지면 DFS가 1,000번 겹쳐 호출되어 `RecursionError`. 간선이 최대(499,500개)인 완전 그래프에서도 DFS가 한 줄로 깊게 들어가 같은 오류가 났다.

## 정답 풀이 (책 풀이 방식)

```python
import sys
sys.setrecursionlimit(10**6)        # 재귀 한도 늘리기 (재귀 DFS의 필수 습관)
input = sys.stdin.readline          # 간선이 최대 약 50만 줄

n, m = map(int, input().split())
a = [[] for _ in range(n + 1)]      # 인접 리스트: a[v] = v와 연결된 노드들
visited = [False] * (n + 1)

def DFS(v):
    visited[v] = True               # 들어오자마자 방문 표시
    for i in a[v]:
        if not visited[i]:
            DFS(i)                  # 안 가본 이웃으로 깊이 들어감

for _ in range(m):
    s, e = map(int, input().split())
    a[s].append(e)                  # 방향이 없으므로 양쪽에 추가
    a[e].append(s)

count = 0
for i in range(1, n + 1):
    if not visited[i]:              # 아직 안 간 노드 = 새로운 묶음의 시작
        count += 1
        DFS(i)                      # 그 묶음 전체를 방문 표시

print(count)
```

- 일렬 1,000개 → `1`, 완전 그래프(간선 499,500개) → `1`, 로컬 약 0.3초.

## 해설

### 연결 요소를 세는 원리
- 아직 안 간 노드 하나에서 DFS를 시작하면, 그 노드와 **이어진 모든 노드**가 방문 표시된다. 즉 묶음 하나를 통째로 칠한다.
- 바깥 `for`는 1번부터 N번까지 보면서 **아직 칠해지지 않은 노드**를 만날 때마다 새 묶음이라고 세고 DFS로 칠한다.
- 그래서 `count`가 늘어나는 횟수 = 묶음의 개수. ([음료수 얼려 먹기](freezing-drinks.md)의 `dfs(i, j) == True`와 같은 구조)

### 예제 1 (`1-2-5`, `3-4-6`)

| 바깥 i | 방문했나 | 동작 | count |
|---|---|---|---|
| 1 | X | DFS(1) → 2 → 5 칠함 | 1 |
| 2 | O | 건너뜀 | 1 |
| 3 | X | DFS(3) → 4 → 6 칠함 | 2 |
| 4 ~ 6 | O | 건너뜀 | 2 |

### 인접 리스트
```
간선: 1-2, 2-5, 5-1, 3-4, 4-6
a[1] = [2, 5]
a[2] = [1, 5]
a[3] = [4]
a[4] = [3, 6]
a[5] = [2, 1]
a[6] = [4]
```
- `[[] for _ in range(n + 1)]`: 노드마다 **따로** 빈 리스트를 만든다. `[[]] * (n + 1)`로 쓰면 모든 칸이 같은 리스트를 공유해서 이웃이 전부 섞인다 ([구간 합 2](../../08-two-pointer-prefix-sum/problems/range-sum-2.md)에서 정리한 `*`와 같은 함정).
- 방향이 없는 간선은 양쪽에서 서로를 이웃으로 가진다 → 두 번 `append`.

### 재귀 한도가 왜 문제인가
- 함수가 자기 자신을 부르면, 끝나지 않은 호출이 **쌓인다**. 일렬 그래프에서는 DFS(1) 안에서 DFS(2), 그 안에서 DFS(3) … 이 1,000층으로 쌓인다.
- Python은 기본적으로 약 **1,000층**까지만 허용해서, 그 이상이면 `RecursionError`로 멈춘다.
- `sys.setrecursionlimit(10**6)`으로 한도를 늘리면 된다. **재귀 DFS를 쓰면 맨 위에 습관처럼 넣는다.**
- 노드가 수십만 개 이상이면 한도를 늘려도 메모리 문제로 실패할 수 있다 → 그럴 땐 스택을 직접 쓰는 반복문 DFS나 BFS ([02 템플릿](../template.py)의 `dfs_iterative`, `bfs`).

### 격자 DFS와 그래프 DFS 비교

| | [음료수 얼려 먹기](freezing-drinks.md) (격자) | 이 문제 (그래프) |
|---|---|---|
| 이웃 찾기 | 상하좌우 `x±1, y±1` | 인접 리스트 `a[v]` |
| 범위 체크 | 필요 (격자 밖) | 필요 없음 (리스트에 있는 이웃만 봄) |
| 방문 표시 | `graph[x][y] = 1` (지도에 직접) | `visited[v] = True` (별도 배열) |
| 묶음 세기 | 바깥 이중 `for` + `dfs`가 True면 +1 | 바깥 `for` + 안 간 노드면 +1 |

## 검증
- 예제 1 → `2`, 예제 2 → `1`
- 노드 1 ~ 15, 간선 무작위 2,000개에서 유니온 파인드로 센 개수와 일치
- 일렬 1,000개, 완전 그래프 1,000개(간선 499,500): 내 풀이 `RecursionError`, 정답 풀이 `1` (약 0.3초)

## 배운 점
- **연결 요소 개수** = 안 간 노드에서 DFS를 시작한 횟수.
- 그래프는 인접 리스트 `[[] for _ in range(n + 1)]`, 방향 없는 간선은 양쪽에 추가.
- **재귀 DFS에는 `sys.setrecursionlimit(10**6)`을 항상.** N이 1,000만 돼도 기본 한도에 걸린다.
