# 03. 그리디

## 핵심 아이디어
매 순간 **지금 가장 좋아 보이는 선택**을 한다. 대부분 "무엇을 기준으로 정렬하느냐"가 문제의 전부다.
그리디가 맞는지 확신이 없으면 **작은 반례**를 손으로 만들어 본다. 반례가 나오면 DP로 넘어간다.

## 이런 문제에서 쓴다
- 회의실 배정, 강의실 배정 → **끝나는 시간** 기준 정렬
- 동전 거스름돈 (큰 단위가 작은 단위의 배수일 때)
- "최대한 많이", "최소 개수로" + 정렬하면 순서가 명확해짐
- 가장 큰/작은 것을 반복해서 꺼냄 → **힙**

## 템플릿 → [template.py](template.py)
- 회의실 배정 (끝나는 시간 정렬)
- 다중 기준 정렬
- 힙으로 가장 작은 두 개 합치기 (카드 정렬)

## 자주 하는 실수
- 정렬 기준을 시작 시간으로 잡음 (회의실 배정은 **끝나는 시간**)
- 동률 처리(2차 기준)를 빼먹음
- 증명 없이 그리디로 밀어붙임 → 반례 확인
- `heapq`는 **최소 힙**. 최대 힙은 값에 `-`를 붙여 넣는다.

## 대표 문제
| 문제 | 떠올렸어야 할 단서 |
|---|---|
| 백준 1931 회의실 배정 | 최대 개수 선택 → 끝나는 시간 정렬 |
| 백준 11047 동전 0 | 단위가 배수 관계 → 큰 것부터 |
| 백준 1715 카드 정렬하기 | 매번 가장 작은 둘 합치기 → 힙 |
| 프로그래머스 구명보트 | 가장 무거운 + 가장 가벼운 → 정렬 + 투 포인터 |
