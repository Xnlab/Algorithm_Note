# 04. 정렬 · 이분탐색

## 핵심 아이디어
- **이분탐색**: 정렬된 범위를 반씩 줄여 O(log n)에 찾기.
- **파라메트릭 서치**: "답이 x일 때 가능한가?"를 판정하는 함수를 만들고, **답 자체를 이분탐색**한다. 가능/불가능이 어느 지점을 기준으로 한 번만 바뀌어야 한다.

## 이런 문제에서 쓴다
- 정렬된 배열에서 값의 존재 여부, 개수 → `bisect`
- 답의 범위가 10⁹ 이상처럼 매우 큼
- "최솟값의 최댓값", "최댓값의 최솟값", "~할 수 있는 최대 길이"
- 랜선 자르기, 나무 자르기, 공유기 설치, 입국심사

## 템플릿 → [template.py](template.py)
- `bisect`로 개수 세기
- 직접 구현한 lower bound
- 파라메트릭 서치 (가능한 최댓값 / 가능한 최솟값)

## 자주 하는 실수
- `lo`, `hi` 초기값이 답의 범위를 다 덮지 못함 (예: 길이는 최소 1인데 0부터 시작해 0으로 나누기)
- `while lo <= hi`와 `while lo < hi`를 섞어 써서 무한 루프 → **한 가지 틀만 외운다**
- 판정 함수의 방향(가능할 때 왼쪽/오른쪽 이동)을 반대로 씀
- 정렬하지 않고 `bisect` 사용

## 대표 문제
| 문제 | 떠올렸어야 할 단서 |
|---|---|
| 백준 10816 숫자 카드 2 | 정렬 + 개수 질의 → bisect |
| 백준 1654 랜선 자르기 | 만들 수 있는 최대 길이 → 파라메트릭 |
| 백준 2110 공유기 설치 | 최소 거리의 최댓값 → 파라메트릭 |
| 프로그래머스 입국심사 | 걸리는 시간의 최솟값, 범위 매우 큼 → 파라메트릭 |
