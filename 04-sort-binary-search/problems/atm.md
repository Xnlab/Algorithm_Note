# ATM 인출 시간 계산하기 (백준 11399 ATM)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 삽입 정렬 / 백준 11399
- **유형**: 정렬 (삽입 정렬 직접 구현) + 그리디 + 누적합
- **푼 날짜**: 2026-11-24
- **결과**: 정답 (책 풀이 방식)

## 문제 요약
N명(N ≤ 1,000)이 ATM 한 대 앞에 줄을 선다. i번 사람이 돈을 뽑는 데 P_i분이 걸릴 때, **각 사람이 기다린 시간 + 자기 인출 시간의 합**이 최소가 되도록 줄을 세우고 그 합을 구한다.

## 떠올렸어야 할 단서
- 앞사람의 시간이 뒤의 **모든 사람에게 더해진다** → 짧은 사람을 앞에 세울수록 이득 → **오름차순 정렬(그리디)**
- 각 사람의 완료 시간 = 앞사람들 시간의 합 = **누적합**, 답 = 누적합의 합
- N ≤ 1,000 → O(N²) 정렬도 충분 → 이 문제는 **삽입 정렬** 연습

## 내 풀이

```python
n = int(input())
a = list(map(int, input().split()))
s = [0] * n

for i in range(1, n):
    ins_i = i
    ins_v = a[i]
    for j in range(i-1, -1, -1):
        if a[j] < a[i]:
            ins_i = j + 1
            break
        if j == 0:
            ins_i = 0
    
    for j in range(i, ins_i, -1):
        a[j] = a[j-1]
    a[ins_i] = ins_v
    
s[0] = a[0]

for i in range(1, n):
    s[i] = s[i-1] + a[i]

sum = 0

for i in range(0, n):
    sum += s[i]
    
print(sum)
```

- 시간복잡도: **O(N²)** (삽입 정렬) + O(N) (누적합)
- 평가
  - 정답. 책 풀이와 같은 방식이다. 예제(32), 중복 값을 포함한 무작위 3,000개에서 정렬 결과와 답 모두 일치, N = 1인 경우도 정상.
  - 삽입 위치를 먼저 찾고 → 그 자리부터 한 칸씩 뒤로 밀고 → 값을 넣는 세 단계가 정확하다.
  - 비교에 `a[i]`를 쓴 것도 괜찮다. 위치를 찾는 동안에는 아직 아무것도 밀지 않아서 `a[i] == ins_v`다. 다만 `ins_v`로 비교하면 의도가 더 분명하다.
  - 주의: 변수 이름 `sum`이 내장 함수를 덮어쓴다. `max`, `sum`에 이어 세 번째라 습관으로 굳히자 → `total`.

## 해설

### 1. 왜 오름차순으로 세우면 최소인가 (그리디)
- k번째 사람의 인출 시간은 **자기 자신 + 뒤에 선 모든 사람**의 대기 시간에 들어간다. 맨 앞 사람의 시간은 N번, 맨 뒤 사람의 시간은 1번 더해진다.
- 그러니 **많이 더해지는 앞자리에 짧은 시간을** 두어야 합이 작아진다.
- 예: 시간 1, 3인 두 사람
  - 1 → 3 순서: 1 + (1+3) = **5**
  - 3 → 1 순서: 3 + (3+1) = 7

### 2. 삽입 정렬의 원리
- 앞쪽 [0, i−1]은 **이미 정렬된 상태**로 유지한다. i번째 값을 꺼내 그 안의 **알맞은 자리에 끼워 넣는다.**
- 카드를 한 장씩 받아 손에 든 카드 사이에 끼워 넣는 것과 같다.

코드의 세 단계:

| 단계 | 코드 | 하는 일 |
|---|---|---|
| ① 위치 찾기 | `for j in range(i-1, -1, -1)` | 뒤에서부터 보며 **나보다 작은 값**을 만나면 그 바로 뒤(`j + 1`)가 내 자리. 끝까지 못 만나면 맨 앞(0) |
| ② 밀기 | `for j in range(i, ins_i, -1): a[j] = a[j-1]` | 내 자리부터 i−1까지를 한 칸씩 **뒤로** 밀어 빈칸을 만든다. 뒤에서부터 밀어야 값이 덮어써지지 않는다 |
| ③ 넣기 | `a[ins_i] = ins_v` | 보관해 둔 값을 빈칸에 넣는다 |

- ② 전에 값을 `ins_v`에 보관해 둔 이유: 밀다 보면 `a[i]` 자리가 앞 값으로 덮어써진다.

### 예제 따라가기 (`3 1 4 3 2`)

| i | 넣을 값 | 들어갈 위치 | 결과 |
|---|---|---|---|
| 1 | 1 | 0 (3보다 작음, 맨 앞) | **1** 3 4 3 2 |
| 2 | 4 | 2 (3 < 4, 그 뒤) | 1 3 **4** 3 2 |
| 3 | 3 | 1 (1 < 3, 그 뒤) | 1 **3** 3 4 2 |
| 4 | 2 | 1 (1 < 2, 그 뒤) | 1 **2** 3 3 4 |

- i = 3에서 비교가 `<`라 같은 값 3을 만나도 멈추지 않고 그 앞까지 간다. 그래서 새 3이 원래 3보다 **앞에** 들어간다. 이 문제는 결과가 같지만, `<=`로 쓰면 같은 값 뒤에서 멈춰 원래 순서가 유지되고(안정 정렬) 미는 횟수도 줄어든다.

### 3. 누적합으로 합 구하기

정렬 후 `1 2 3 3 4`:

| 사람 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 인출 시간 a | 1 | 2 | 3 | 3 | 4 |
| 끝나는 시각 s (누적합) | 1 | 3 | 6 | 9 | 13 |

답 = 1 + 3 + 6 + 9 + 13 = **32**

### 참고: 실전에서는
```python
n = int(input())
a = sorted(map(int, input().split()))
total = 0
acc = 0
for x in a:
    acc += x          # 이 사람이 끝나는 시각
    total += acc
print(total)
```
- 정렬은 `sorted`, 누적합 배열 없이 변수 하나로 바로 더해도 된다.

### 정렬 세 가지 비교

| | 버블 | 선택 | 삽입 |
|---|---|---|---|
| 방법 | 이웃끼리 바꿔 큰 값을 뒤로 | 최댓값(최솟값)을 찾아 맨 앞으로 | 정렬된 앞쪽에 하나씩 끼워 넣기 |
| 최악 | O(N²) | O(N²) | O(N²) |
| 거의 정렬된 입력 | 빠름 (조기 종료 시) | 항상 O(N²) | **빠름** (거의 안 밀어도 됨) |
| 안정 정렬 | O | X | O (`<=`로 멈출 때) |

## 검증
- 예제 `3 1 4 3 2` → `32`
- 길이 1 ~ 20, 값 1 ~ 8(중복 포함) 무작위 3,000개에서 정렬 결과와 답 모두 `sorted` + 직접 합산과 일치
- N = 1 → 입력값 그대로, N = 1,000 → 로컬 약 0.05초

## 배운 점
- 앞의 값이 뒤에 계속 더해지는 구조 → **작은 것부터(오름차순)** 가 최소. 답은 누적합의 합.
- 삽입 정렬: 위치 찾기 → 뒤에서부터 밀기 → 넣기. 밀기 전에 값을 보관한다.
- 내장 함수 이름(`sum`, `max`, `min`, `list`)을 변수로 쓰지 않는다.
