# 버블 정렬 프로그램 1 (백준 1377 버블 소트)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 버블 정렬 / 백준 1377
- **유형**: 정렬 (버블 정렬의 성질 이용)
- **푼 날짜**: 2026-11-23
- **결과**: 정답 (책 풀이 방식)

## 문제 요약
N개(N ≤ 500,000)의 수에 대해, "한 회차 동안 교환이 한 번도 없으면 그 회차 번호 i를 출력하고 멈추는" 버블 정렬 코드가 주어진다. 이 코드가 **출력하는 값**을 구한다. 같은 값이 여러 개 있을 수 있다.

## 떠올렸어야 할 단서
- N이 50만 → 버블 정렬을 그대로 돌리면 O(N²) = 2,500억 → 불가능. 정렬 **과정을 흉내 내지 말고 성질로** 답을 구해야 한다
- 버블 정렬의 성질: 한 회차에 큰 수는 끝까지 갈 수 있지만, **작은 수는 왼쪽으로 딱 한 칸만** 이동한다
- → 각 수가 **왼쪽으로 몇 칸 가야 하는지**의 최댓값 = 교환이 일어나는 회차 수
- 정렬 전 위치와 정렬 후 위치만 알면 된다 → `(값, 원래 인덱스)`로 묶어 정렬 O(N log N)

## 내 풀이

```python
n = int(input())
a = []

for i in range(n):
    a.append((int(input()), i))

max = 0
sorted_a = sorted(a)

for i in range(n):
    if max < sorted_a[i][1] - i:
        max = sorted_a[i][1] - i

print(max + 1)
```

- 시간복잡도: **O(N log N)** (정렬)
- 평가
  - 정답. 책 풀이와 같은 방식이다. 문제 속 버블 정렬 코드를 직접 돌린 결과와, 중복 값을 포함한 무작위 3,000개에서 모두 일치.
  - `(값, 원래 인덱스)` 튜플로 정렬해 **같은 값의 순서가 원래대로 유지**되게 한 것이 정확하다 (아래 해설).
  - 주의 1: 입력이 최대 50만 줄 → `input = sys.stdin.readline`을 넣으면 로컬 기준 0.64초 → 0.40초.
  - 주의 2: 변수 이름 `max`가 내장 함수 `max()`를 덮어쓴다 ([연속된 자연수의 합](../../08-two-pointer-prefix-sum/problems/consecutive-sum.md)의 `sum`과 같은 문제). `max_move` 같은 이름이 안전하다.

## 해설

### 큰 수와 작은 수가 움직이는 방식이 다르다
버블 정렬의 한 회차는 왼쪽부터 이웃끼리 비교해서 앞이 더 크면 바꾼다.

- **큰 수**: 한 번 바뀌어 오른쪽으로 가면, 다음 비교에서도 또 앞에 서게 된다 → 한 회차에 **여러 칸** 오른쪽으로 갈 수 있다.
- **작은 수**: 바로 왼쪽 수와 한 번 바뀌어 한 칸 왼쪽으로 가면, 비교 위치는 이미 그 오른쪽으로 넘어갔다 → 한 회차에 **왼쪽으로 최대 한 칸**.

예: `10 1 5 2 3` 1회차 → `1 5 2 3 10`
- 10은 한 번에 끝까지(4칸) 갔다.
- 1, 2, 3은 각각 왼쪽으로 한 칸씩만 왔다.

### 그래서 답은 "왼쪽 이동 거리의 최댓값 + 1"
- 어떤 수가 왼쪽으로 k칸 가야 한다면, 최소 k회차 동안 교환이 일어난다.
- 왼쪽으로 가야 할 거리가 가장 큰 수가 자리를 잡는 회차까지 교환이 계속되고, **그다음 회차**는 교환이 없어 그 번호가 출력된다 → `최댓값 + 1`.
- 왼쪽 이동 거리 = **원래 위치 − 정렬 후 위치** = `sorted_a[i][1] - i`
  - 오른쪽으로 가는 수는 이 값이 음수라 최댓값에 영향을 주지 않는다.
- 이미 정렬된 입력이면 최댓값 0 → 1회차에 교환이 없어 `1` 출력.

### 예제 (`10 1 5 2 3`)

| 값 | 원래 위치 | 정렬 후 위치 | 왼쪽 이동 |
|---|---|---|---|
| 1 | 1 | 0 | 1 |
| 2 | 3 | 1 | **2** |
| 3 | 4 | 2 | **2** |
| 5 | 2 | 3 | −1 |
| 10 | 0 | 4 | −4 |

최댓값 2 → 답 **3** (1, 2회차에 교환, 3회차에 교환 없음)

### 같은 값이 있을 때: 튜플 정렬이 중요한 이유
- 문제의 버블 정렬은 `A[j] > A[j+1]`일 때만 바꾼다. **같은 값끼리는 절대 안 바꾼다** → 같은 값의 원래 순서가 그대로 유지된다(안정 정렬).
- 그러니 "정렬 후 위치"도 같은 값끼리는 **원래 순서대로** 놓였다고 계산해야 한다.
- `(값, 원래 인덱스)`로 정렬하면 값이 같을 때 인덱스가 작은 쪽이 앞에 와서 정확히 그 순서가 된다. ([성적 순 출력](low-score-order.md)에서 본 안정 정렬, [절댓값 힙](../../09-stack-queue/problems/abs-heap.md)의 튜플 2단계 비교와 같은 원리)

### 이 문제에서 배울 점
- 문제가 "이 코드의 출력을 구하라"고 하면, 코드를 그대로 돌리는 게 아니라 **그 코드가 가진 성질**을 찾아 빠르게 계산하라는 신호인 경우가 많다.
- 그래서 [수 정렬하기 1](sort-numbers-1.md)에서 버블 정렬을 직접 짜 보며 "작은 수는 한 칸씩만 앞으로 온다"를 관찰해 둔 것이 여기서 바로 쓰인다.

## 검증
- 예제 `10 1 5 2 3` → `3`
- 길이 1 ~ 15, 값 0 ~ 6(중복 포함) 무작위 3,000개에서 문제의 버블 정렬 코드를 그대로 실행한 결과와 일치
- N = 500,000 → 로컬 약 0.64초 (`sys.stdin.readline` 사용 시 약 0.40초)

## 배운 점
- 버블 정렬 한 회차: 큰 수는 여러 칸 오른쪽, **작은 수는 왼쪽으로 한 칸만** → 회차 수 = 왼쪽 이동 거리의 최댓값.
- "정렬 전후 위치"가 필요하면 `(값, 원래 인덱스)`로 묶어 정렬한다. 같은 값의 순서도 원래대로 유지된다.
- 코드의 출력을 묻는 문제는 시뮬레이션 대신 성질을 찾는다.
