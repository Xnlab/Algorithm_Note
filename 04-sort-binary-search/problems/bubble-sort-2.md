- **푼 날짜**: 2026-11-26
- **결과**: 정답 — 풀이를 일부 참고함 → **회독 대상**

## 문제 요약
수 N개(N ≤ 500,000, |값| ≤ 10⁹, 중복 가능)를 버블 정렬할 때 **교환(swap)이 몇 번 일어나는지** 구한다.

## 떠올렸어야 할 단서
- N이 50만 → 버블 정렬을 그대로 돌리면 O(N²) = 2,500억 → 불가능
- 버블 정렬의 교환 = **이웃한 두 수의 순서가 틀렸을 때** 한 번 → 교환 횟수 = **순서가 뒤집힌 쌍(i < j인데 a[i] > a[j])의 개수**
- 그 쌍의 개수는 **병합 정렬의 합치기 과정**에서 O(N log N)에 셀 수 있다
- 답이 최대 약 1,250억 → Python은 큰 정수 문제없음 (다른 언어는 `long long`)

## 내 풀이

```python
result = 0

def merge(s, e):
    global result
    if e - s < 1:
        return
    m = int(s + (e - s) / 2)
    merge(s, m)
    merge(m + 1, e)
    
    for i in range(s, e+1):
        tmp[i] = a[i]
        
    i1 = s
    i2 = m + 1
    k = s
    
    while i1 <= m and i2 <= e:
        if tmp[i1] > tmp[i2]:
            a[k] = tmp[i2]
            result += i2 - k
            k += 1
            i2 += 1
        else:
            a[k] = tmp[i1]
            k += 1
            i1 += 1
    
    while i1 <= m:
        a[k] = tmp[i1]
        k += 1
        i1 += 1
    
    while i2 <= e:
        a[k] = tmp[i2]
        k += 1
        i2 += 1
    
n = int(input())
a = list(map(int, input().split()))
a.insert(0, 0)
tmp = [0] * int(n + 1)

merge(1, n)
print(result)
```

- 시간복잡도: **O(N log N)**
- 평가
  - 정답. 병합 정렬([수 정렬하기 2](sort-numbers-2.md))에 **`result += i2 - k` 한 줄**만 더한 구조다.
  - 중복·음수를 포함한 무작위 3,000개에서, 버블 정렬을 실제로 돌려 센 교환 횟수와 모두 일치.
  - `a.insert(0, 0)`으로 맨 앞에 0을 끼워 1번 칸부터 쓰게 한 것도 [수 정렬하기 2](sort-numbers-2.md)의 1-index 방식과 맞다.
  - 주의: N = 500,000에서 로컬 약 **2.1초**. 백준에서는 Python 3로 시간 초과가 나기 쉬워 **PyPy3** 제출을 권한다.

## 해설

### 1. 교환 횟수 = 뒤집힌 쌍의 개수
- 버블 정렬은 **이웃한 두 수**가 순서가 틀릴 때만 바꾼다. 바꿀 때마다 "순서가 틀린 쌍"이 **정확히 하나** 줄어든다 (그 두 수의 순서만 바뀌고, 다른 수들과의 앞뒤 관계는 그대로).
- 정렬이 끝나면 틀린 쌍은 0개 → **교환 횟수 = 처음에 있던 틀린 쌍의 수**.
- 예: `3 2 1` → 틀린 쌍 (3,2) (3,1) (2,1) = 3개 → 교환 3번.

### 2. 합치기에서 틀린 쌍 세기
병합 정렬의 합치기에서, **오른쪽 줄의 값이 먼저 나갈 때**를 보자.

- 그 값은 원래 오른쪽(뒤쪽)에 있었는데, 왼쪽 줄에 **아직 남아 있는 값들보다 작아서** 그들보다 앞으로 간다.
- 왼쪽에 남은 값들은 모두 그 값보다 앞에 있었고, 더 크다 → 남은 개수만큼 **틀린 쌍**이다.
- 왼쪽 줄의 값이 먼저 나갈 때는 아무도 앞지르지 않으므로 0.

### 3. `i2 - k`가 바로 "왼쪽에 남은 개수"
- `i2`: 오른쪽 값의 원래 자리, `k`: 그 값이 새로 들어갈 자리.
- `i2 - k` = 그 값이 **왼쪽으로 몇 칸 이동했나** = 앞지른 값의 수 = 왼쪽에 남은 개수 `m - i1 + 1`.
- 실행하며 매번 `i2 - k == m - i1 + 1`인지 확인했고, 항상 같았다. 책에 따라 둘 중 어느 식으로 써도 된다.

### 예제 따라가기 (`5 2 4 1 3`, 실제 실행 기록)

| 합치기 | 결과 | 이번에 센 수 | 누적 |
|---|---|---|---|
| [5] + [2] | 2 5 | 2가 5를 앞지름 → 1 | 1 |
| [2 5] + [4] | 2 4 5 | 4가 5를 앞지름 → 1 | 2 |
| [1] + [3] | 1 3 | 0 | 2 |
| [2 4 5] + [1 3] | 1 2 3 4 5 | 아래 표 → 5 | **7** |

마지막 합치기 자세히:

| 나가는 값 | 왼쪽에 남은 값 | 더하는 수 |
|---|---|---|
| 오른쪽 1 | 2 4 5 | +3 |
| 왼쪽 2 | | +0 |
| 오른쪽 3 | 4 5 | +2 |
| (나머지 4 5는 그대로) | | |

→ 총 **7**. 버블 정렬을 실제로 돌려 센 교환 횟수도 7.

### 4. 같은 값일 때
- 버블 정렬은 `>`일 때만 바꾸므로 **같은 값끼리는 교환하지 않는다.**
- 합치기에서도 `tmp[i1] > tmp[i2]`일 때만 오른쪽을 먼저 보내고, 같으면 왼쪽을 먼저 보낸다 → 같은 값은 앞지르기로 세지 않는다. 그래서 중복이 있어도 정확하다.
- `>=`로 쓰면 같은 값도 세서 답이 커진다.

### [버블 정렬 프로그램 1](bubble-sort-1.md)과 비교

| | 프로그램 1 | 프로그램 2 |
|---|---|---|
| 묻는 것 | 몇 **회차**에 끝나나 | 교환이 **몇 번** 일어나나 |
| 쓰는 성질 | 작은 수는 회차마다 왼쪽으로 한 칸 | 교환 1번 = 틀린 쌍 1개 해소 |
| 계산 | (원래 위치 − 정렬 위치)의 최댓값 + 1 | 병합 정렬 합치기에서 앞지른 수 합 |
| 시간 | O(N log N) (정렬) | O(N log N) (병합 정렬) |

## 검증
- 예제 `3 2 1` → `3`
- 길이 1 ~ 25, 값 −5 ~ 5(중복 포함) 무작위 3,000개에서 버블 정렬을 실제로 실행해 센 교환 횟수와 일치
- N = 500,000 → 로컬 약 2.1초

## 배운 점
- **버블 정렬 교환 횟수 = 뒤집힌 쌍(inversion)의 개수.**
- 병합 정렬 합치기에서 **오른쪽 값이 먼저 나갈 때, 왼쪽에 남은 개수**(= `i2 - k`)를 더하면 뒤집힌 쌍을 O(N log N)에 셀 수 있다.
- 병합 정렬을 직접 짜 본 이유가 이것. "정렬"이 아니라 "정렬하는 과정에서 무엇이 일어나는가"를 묻는 문제에 쓰인다.
