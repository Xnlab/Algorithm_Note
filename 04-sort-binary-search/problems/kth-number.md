# K번째 수 구하기 (백준 11004 K번째 수)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 퀵 정렬 / 백준 11004
- **유형**: 퀵 선택 (퀵 정렬의 분할 이용)
- **푼 날짜**: 2026-11-25
- **결과**: 오답 (재귀 조건 반대 + 분할 경계 버그)

## 문제 요약
수 N개(N ≤ 5,000,000)를 오름차순으로 정렬했을 때 앞에서 K번째 수를 구한다.

## 떠올렸어야 할 단서
- "정렬했을 때 K번째" → 정렬 후 인덱스 K−1. **`sort()` 한 줄로 가능**
- 전체를 정렬할 필요 없이 K번째 **자리만** 확정하면 된다 → 퀵 정렬의 분할(partition)을 K가 있는 쪽으로만 반복하는 **퀵 선택**, 평균 O(N)

## 내 풀이

```python
n, k = map(int, input().split())
a = list(map(int, input().split()))

def quick(s, e, k):
    global a
    if s > e:
        pivot = partition(s, e)
        if pivot == k:
            return
        elif k < pivot:
            quick(s, pivot-1, k)
        else:
            quick(pivot+1, e, k)

def swap(i, j):
    global a
    temp = a[i]
    a[i] = a[j]
    a[j] = temp
    
def partition(s, e):
    global a
    
    if s + 1 == e:
        if a[s] > a[e]:
            swap(s, e)
        return e
    
    m = (s + e) // 2
    swap(s, m)
    pivot = a[s]
    i = s + 1
    j = e
    
    while i <= j:
        while pivot < a[j] and j > 0:
            j = j - 1
        while pivot > a[i] and i < len(a)-1:
            i = i + 1
        if i <= j:
            swap(i, j)
            i = i + 1
            j = j - 1
    
    a[s] = a[j]
    a[j] = pivot
    return j

quick(0, n-1, k-1)
print(a[k-1])
```

- 시간복잡도: 평균 **O(N)** (분할 한 번 O(구간 길이), 매번 한쪽만 들어감)
- 평가: 퀵 선택 구조(중간값을 피벗으로 → 분할 → K가 있는 쪽만 재귀)는 맞다. 하지만 버그 두 개로 답이 틀린다.

### 버그 목록

| # | 위치 | 문제 | 결과 | 수정 |
|---|---|---|---|---|
| 1 | `if s > e:` | 조건이 **반대**. 처음 호출 `quick(0, n-1)`에서 0 > n−1이 거짓이라 **분할을 한 번도 안 함** | 입력 그대로의 `a[k-1]` 출력. 예제 `4 1 2 3 5`, K = 2 → **1** (정답 2) | `if s < e:` |
| 2 | `i < len(a)-1` | i의 한계를 **구간 끝 e가 아니라 배열 끝**으로 잡음. 구간이 배열 끝까지일 때, 마지막 원소가 피벗보다 작아도 i가 거기서 멈춤 → i == j인 칸을 자기 자신과 교환하고 j가 한 칸 더 내려감 | 피벗이 **한 칸 왼쪽**에 놓여, 피벗 오른쪽에 더 작은 값이 남음 | `while i <= e and pivot > a[i]:` |

### 버그 2 추적 (`0 2 1`, K = 2)

| 단계 | 상태 |
|---|---|
| 중간값 2를 맨 앞으로 | `2 0 1`, pivot = 2, i = 1, j = 2 |
| j: 2 < 1 아님 → 멈춤 | j = 2 |
| i: 2 > 0 → i = 2, 2 > 1이지만 `i < len(a)-1`이 거짓 → **멈춤** | i = 2 |
| i ≤ j → 자기 자신과 교환, i = 3, **j = 1** | `2 0 1` |
| 피벗을 j = 1에 놓음 | `0 2 1` ← 2 오른쪽에 1이 남음 |
| pivot(1) == K−1(1) → 종료 | 출력 **2** (정답 1) |

- i가 조건(`pivot > a[i]`)이 아니라 **한계** 때문에 멈추면, 그 칸은 "피벗보다 작은 값"인데 큰 값 자리로 취급된다.
- `i <= e`로 바꾸면 i가 e + 1까지 넘어가 반복이 끝나고, j = e가 그대로 남아 피벗이 맨 끝(올바른 자리)에 놓인다.

### 버그별 영향 (직접 실행해서 확인)
- 원래 코드: 길이 1 ~ 20 무작위 3,000개 중 **2,213개 오답**
- 버그 1만 고침: **222개 오답**. 길이 1 ~ 5 전수 검사에서도 `0 2 1`, `0 1 0` 같은 작은 입력이 틀림. 중복 없는 순열에서도 틀린다.
- 버그 1, 2 모두 고침: 길이 1 ~ 6, 값 0 ~ 3 **전수 30,948개** + 무작위 3,000개 모두 정답

## 정답 풀이 (책 풀이 방식, 두 군데 수정)

```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

def quick(s, e, k):
    if s < e:                                   # 수정 1
        pivot = partition(s, e)
        if pivot == k:                          # K번째 자리가 확정됨
            return
        elif k < pivot:                         # K가 왼쪽 그룹에 있음
            quick(s, pivot - 1, k)
        else:                                   # K가 오른쪽 그룹에 있음
            quick(pivot + 1, e, k)

def swap(i, j):
    a[i], a[j] = a[j], a[i]

def partition(s, e):
    if s + 1 == e:                              # 원소 2개: 직접 비교
        if a[s] > a[e]:
            swap(s, e)
        return e

    m = (s + e) // 2
    swap(s, m)                                  # 중간값을 피벗으로, 맨 앞에 둠
    pivot = a[s]
    i = s + 1
    j = e

    while i <= j:
        while pivot < a[j] and j > 0:           # 오른쪽에서 피벗 이하인 값 찾기
            j = j - 1
        while i <= e and pivot > a[i]:          # 수정 2: 왼쪽에서 피벗 이상인 값 찾기 (구간 안에서만)
            i = i + 1
        if i <= j:
            swap(i, j)
            i = i + 1
            j = j - 1

    a[s] = a[j]                                 # 피벗을 경계 j에 놓음
    a[j] = pivot
    return j

quick(0, n - 1, k - 1)
print(a[k - 1])
```

- `global a`: 함수 안에서 `a[i] = ...`처럼 **리스트 안의 칸만** 바꾸므로 없어도 된다 ([DNA 비밀번호](../../08-two-pointer-prefix-sum/problems/dna-password.md)에서 본 것과 같은 이유).

## `sort`로도 되나? → 된다

```python
import sys
input = sys.stdin.readline
n, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()
print(a[k - 1])
```

- 무작위 3,000개 모두 정답.
- N = 5,000,000에서 로컬 시간: `sort` 약 4.2초, 고친 퀵 선택 약 3.2초 (둘 다 500만 개 입력을 읽는 시간이 큰 비중). 백준에서는 Python 3로 빠듯할 수 있어 **PyPy3** 제출을 권한다.
- 실전에서는 `sort`가 버그 위험이 없어 먼저 쓸 만하다. 퀵 선택은 "전체 정렬 없이 K번째만" 필요한 원리를 익히는 용도.

## 해설

### 퀵 정렬의 분할(partition)
- 피벗 하나를 골라, **피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽**으로 보내고 피벗을 그 사이에 놓는다.
- 분할이 끝나면 **피벗의 자리는 최종 정렬 위치로 확정**된다. 왼쪽 그룹·오른쪽 그룹 안의 순서는 아직 모른다.

### 퀵 정렬 vs 퀵 선택

| | 퀵 정렬 | 퀵 선택 |
|---|---|---|
| 분할 후 | 왼쪽·오른쪽 **둘 다** 재귀 | K가 있는 **한쪽만** 재귀 |
| 끝나는 조건 | 구간 길이 1 이하 | 피벗 자리 == K |
| 평균 시간 | O(N log N) | **O(N)** (N + N/2 + N/4 + … ≈ 2N) |
| 최악 | O(N²) | O(N²) |

- 중간 위치 값을 피벗으로 쓰는 이유: 이미 정렬된 입력에서 맨 앞 값을 피벗으로 쓰면 매번 한쪽으로 쏠려 O(N²)이 된다.

### 분할에서 i와 j의 역할
- j: 오른쪽 끝에서 왼쪽으로 오며 **피벗 이하**인 값에서 멈춤 (왼쪽으로 보내야 할 값)
- i: 왼쪽에서 오른쪽으로 가며 **피벗 이상**인 값에서 멈춤 (오른쪽으로 보내야 할 값)
- 둘 다 멈췄고 i ≤ j면 서로 바꾼다. i > j가 되면 j가 "작은 그룹의 마지막 칸" → 맨 앞에 있던 피벗을 j와 바꿔 경계에 놓는다.
- **포인터는 반드시 구간 [s, e] 안에서만** 움직여야 한다. 버그 2는 i의 한계를 배열 전체로 잡아서 생겼다.

## 검증
- 예제 `5 2 / 4 1 2 3 5` → 원래 코드 `1`, 정답 풀이 `2`
- 길이 1 ~ 6, 값 0 ~ 3 전수 30,948개 + 길이 1 ~ 40 무작위 3,000개: 정답 풀이·`sort` 모두 정답
- N = 5,000,000 → `sort` 약 4.2초, 퀵 선택 약 3.2초 (로컬)

## 배운 점
- **"정렬했을 때 K번째"** → `sort()` 후 `a[k-1]`. 원리를 묻는다면 퀵 선택(분할 후 K 쪽만).
- 재귀의 계속 조건은 "구간에 원소가 2개 이상" → `s < e`. 부등호 방향을 한 번 더 확인한다.
- 분할의 포인터 한계는 **구간 끝 e**. 배열 끝(`len(a)-1`)으로 잡으면 구간이 배열 끝까지일 때 틀린다.
- 예제가 맞아도 `0 2 1` 같은 **3개짜리 작은 입력**을 전부 넣어 보면 경계 버그가 바로 드러난다.
