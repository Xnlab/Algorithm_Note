## 문제 요약
서로 다른 정수 N개(N ≤ 1,000,000)를 오름차순으로 정렬해 한 줄에 하나씩 출력한다.

## 떠올렸어야 할 단서
- N이 100만 → O(N²) 정렬(버블·선택·삽입)은 1조 번 → 불가능. **O(N log N)** 이 필요
- 직접 구현한다면 **병합 정렬**: 반으로 쪼개고, 정렬된 두 묶음을 합치기를 반복
- 실전에서는 `sort()` 한 줄 (아래 참고)

## 따라 쓴 풀이 (책 풀이)

```python
def merge_sort(s, e):
    if e-s < 1:
        return
    m = int(s + (e-s) / 2)
    merge_sort(s, m)
    merge_sort(m+1, e)
    for i in range(s, e+1):
        tmp[i] = a[i]
    k = s
    index1 = s
    index2 = m+1
    
    while index1<=m and index2<=e:
        if tmp[index1] > tmp[index2]:
            a[k] = tmp[index2]
            k+=1
            index2+=1
        else:
            a[k] = tmp[index1]
            k+=1
            index1+=1
    
    while index1<=m:
        a[k] = tmp[index1]
        k+=1
        index1+=1
    while index2<=e:
        a[k] = tmp[index2]
        k+=1
        index2+=1

n = int(input())
a = [0] * int(n+1)
tmp = [0] * int(n+1)

for i in range(1, n+1):
    a[i] = int(input())
    
merge_sort(1, n)

for i in range(1, n+1):
    print(a[i], end='\n')
```

- 시간복잡도: **O(N log N)**
- 정확성: 예제와 무작위 2,000개에서 `sorted()` 결과와 일치.
- 주의: Python으로 직접 짠 병합 정렬은 N = 1,000,000에서 로컬 약 **5.5초**. 백준에 Python 3로 내면 시간 초과가 나기 쉽다. 원리 연습용이고, 제출은 `sort()` 또는 PyPy3.

## 해설 (처음 보는 사람용)

### 한 문장 요약
> **잘게 쪼개서 한 개짜리로 만들고, 정렬된 묶음 두 개를 앞에서부터 비교하며 합치는 걸 반복한다.**

### 핵심 아이디어: "정렬된 두 줄을 합치는 건 쉽다"
- 키 순서대로 선 두 줄이 있다고 하자: `[2, 4, 5]`, `[1, 3]`
- 두 줄의 **맨 앞 사람끼리만** 비교해서 작은 사람을 새 줄로 보내면 된다. 각 줄은 이미 정렬되어 있으니, 맨 앞이 그 줄에서 가장 작다.
- 이걸 반복하면 합친 줄도 정렬된다. 한 번 비교할 때마다 한 명씩 나가므로 **두 줄 길이의 합만큼만** 비교하면 끝난다.

| 단계 | 왼쪽 맨 앞 | 오른쪽 맨 앞 | 작은 쪽 | 합친 줄 |
|---|---|---|---|---|
| 1 | 2 | 1 | 1 (오른쪽) | 1 |
| 2 | 2 | 3 | 2 (왼쪽) | 1 2 |
| 3 | 4 | 3 | 3 (오른쪽) | 1 2 3 |
| 4 | 4 | (끝) | 남은 왼쪽 그대로 | 1 2 3 4 5 |

### 그럼 "정렬된 두 줄"은 어디서 오나? → 쪼개서 만든다
- 한 개짜리 줄은 **이미 정렬된 상태**다 (비교할 대상이 없으니까).
- 그래서 전체를 반, 또 반으로 쪼개서 한 개짜리로 만든 다음, 두 개씩 합치고, 그걸 또 합치면서 올라온다.

`5 2 4 1 3`으로 실제 실행한 기록:

```
[1~5] 5 2 4 1 3 → 쪼개기: [1~3] + [4~5]
  [1~3] 5 2 4 → 쪼개기: [1~2] + [3~3]
    [1~2] 5 2 → 쪼개기: [1~1] + [2~2]
      [1~1] 5 → 한 개라 그대로
      [2~2] 2 → 한 개라 그대로
    [1~2] 합치기: [5] + [2] → [2, 5]
    [3~3] 4 → 한 개라 그대로
  [1~3] 합치기: [2, 5] + [4] → [2, 4, 5]
  [4~5] 1 3 → 쪼개기: [4~4] + [5~5]
    ...
  [4~5] 합치기: [1] + [3] → [1, 3]
[1~5] 합치기: [2, 4, 5] + [1, 3] → [1, 2, 3, 4, 5]
```

### 코드를 부분별로

**① 멈추는 조건**
```python
if e - s < 1:
    return
```
- 구간 [s, e]에 원소가 **한 개 이하**면 이미 정렬된 것 → 아무것도 안 하고 돌아간다.

**② 반으로 쪼개서 각각 정렬**
```python
m = int(s + (e - s) / 2)     # 가운데 위치 ((s + e) // 2와 같다)
merge_sort(s, m)             # 왼쪽 절반 정렬
merge_sort(m + 1, e)         # 오른쪽 절반 정렬
```
- 함수가 자기 자신을 부르는 **재귀**. "왼쪽 반을 정렬해 줘"를 같은 함수에 맡긴다.
- 이 두 줄이 끝나면 a[s ~ m]과 a[m+1 ~ e]가 **각각 정렬된 상태**가 된다.

**③ 합치기 전에 복사해 두기**
```python
for i in range(s, e + 1):
    tmp[i] = a[i]
```
- 합친 결과를 다시 `a`에 써 넣을 건데, 그러면 아직 안 읽은 값이 덮어써질 수 있다. 그래서 원본을 `tmp`에 복사해 두고, **읽기는 tmp에서, 쓰기는 a에** 한다.

**④ 두 줄의 맨 앞끼리 비교하며 합치기**
```python
k = s              # a에 다음 값을 쓸 자리
index1 = s         # 왼쪽 줄의 맨 앞
index2 = m + 1     # 오른쪽 줄의 맨 앞

while index1 <= m and index2 <= e:     # 두 줄 모두 남아 있는 동안
    if tmp[index1] > tmp[index2]:      # 오른쪽 맨 앞이 더 작으면
        a[k] = tmp[index2]; index2 += 1
    else:                              # 왼쪽 맨 앞이 작거나 같으면
        a[k] = tmp[index1]; index1 += 1
    k += 1
```
- 포인터 세 개: `index1`(왼쪽 줄에서 볼 차례), `index2`(오른쪽 줄에서 볼 차례), `k`(결과를 쓸 자리).
- 작은 쪽을 a[k]에 쓰고, **그 줄의 포인터와 k만** 한 칸 전진한다.
- 같을 때 왼쪽을 먼저 보내서 같은 값의 원래 순서가 유지된다 (안정 정렬).

**⑤ 남은 쪽 붙이기**
```python
while index1 <= m:  a[k] = tmp[index1]; k += 1; index1 += 1
while index2 <= e:  a[k] = tmp[index2]; k += 1; index2 += 1
```
- 한쪽 줄이 먼저 끝나면, 다른 쪽에 남은 값들은 이미 정렬되어 있고 지금까지 보낸 값들보다 크다 → 그대로 뒤에 붙인다. 두 반복 중 하나만 실제로 돈다.

**⑥ 1번 칸부터 쓰는 이유**
- `a = [0] * (n + 1)`로 만들고 1 ~ n번 칸을 쓴다. 문제 번호와 인덱스를 맞추려는 책의 스타일이고, 0번 칸은 안 쓴다. 0부터 써도 `merge_sort(0, n - 1)`로 바꾸면 똑같이 동작한다.

### 왜 O(N log N)인가
- **쪼개는 단계 수**: 길이 N을 반씩 나누면 log₂N 단계 만에 한 개짜리가 된다 (100만 → 약 20단계).
- **각 단계에서 합치는 일**: 한 단계의 모든 합치기를 더하면 원소 N개를 한 번씩 옮기는 것 → N.
- 합치면 **N × log N**. 100만이면 약 2,000만 번으로, O(N²)의 1조 번과 비교가 안 된다.

### 실전에서는
```python
import sys
input = sys.stdin.readline
n = int(input())
a = [int(input()) for _ in range(n)]
a.sort()
print('\n'.join(map(str, a)))
```
- 같은 입력에서 로컬 약 **0.6초** (직접 짠 병합 정렬 약 5.5초). Python의 `sort()`는 C로 구현되어 있고 내부적으로 병합 정렬 계열(Timsort)이라 같은 O(N log N)이어도 훨씬 빠르다.
- 병합 정렬을 직접 짜 보는 이유: 합치는 과정에서 **"오른쪽 값이 왼쪽의 몇 개를 앞질렀는가"** 를 세면 버블 정렬의 교환 횟수를 O(N log N)에 구할 수 있다 (다음 문제 '버블 정렬 프로그램 2'). 원리를 알아야 그런 응용이 가능하다.

## 검증
- 예제 `5 4 3 2 1` → `1 2 3 4 5`
- 길이 1 ~ 40 무작위 2,000개에서 `sorted()`와 일치
- N = 1,000,000 → 병합 정렬 약 5.5초, `sort()` + `join` 약 0.6초 (로컬)

## 배운 점
- 병합 정렬 = **반으로 쪼개기(재귀) + 정렬된 두 줄 합치기(포인터 두 개)**.
- 합칠 때는 원본을 복사해 두고 **tmp에서 읽고 a에 쓴다.**
- 한쪽이 끝나면 남은 쪽을 그대로 붙인다.
- 실전 제출은 `sort()`. 직접 구현은 원리와 응용(교환 횟수 세기)을 위해.
