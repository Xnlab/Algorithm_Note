# 수 정렬하기 3 (백준 10989)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 기수 정렬 / 백준 10989
- **유형**: 정렬 (계수 정렬 = 개수 세기)
- **푼 날짜**: 2026-11-26
- **결과**: 오답 (변수 이름 불일치로 `NameError`) — 고치면 정답

## 문제 요약
N개(N ≤ 10,000,000)의 자연수를 오름차순으로 한 줄에 하나씩 출력한다. 각 수는 **10,000 이하**. 메모리 제한이 매우 작다.

## 떠올렸어야 할 단서
- N은 1,000만인데 **값의 범위는 1 ~ 10,000으로 작다** → 수를 다 저장하지 말고 **값마다 몇 번 나왔는지만** 센다 (계수 정렬)
- 메모리 제한이 작음 → 1,000만 개를 리스트에 담는 순간 초과. 크기 10,001짜리 개수 배열만 쓴다
- 입력 1,000만 줄 → `sys.stdin.readline` 필수

## 내 풀이

```python
n = int(input())
a = [0] * 10001

for i in range(n):
    a[int(input())] += 1

for i in range(10001):
    if count[i] != 0:
        for _ in range(count[i]):
            print(i)
```

- 시간복잡도: **O(N + K)** (N = 수의 개수, K = 값의 범위 10,000)
- 평가
  - 아이디어(값을 인덱스로 써서 개수 세기 → 0부터 순서대로 개수만큼 출력)는 정확하다.
  - **버그**: 개수 배열을 `a`로 만들었는데 출력에서는 `count`로 씀 → `NameError: name 'count' is not defined`. 책 코드는 `count`인데 앞부분만 이름을 바꾼 것으로 보인다. ([게임 개발](../../01-implementation/problems/game-development.md)의 `left` / `turn_left`와 같은 종류)
  - `count[i]` → `a[i]`로 바꾸면 무작위 1,000개 모두 정답.
  - 주의: N = 1,000만에서 `input()` / `print()`로는 로컬 약 **18.7초**. 아래 정답 풀이(`readline` / `write`)는 약 **5.3초**.

## 정답 풀이 (책 풀이 방식)

```python
import sys
input = sys.stdin.readline
write = sys.stdout.write

n = int(input())
count = [0] * 10001                 # count[v] = 값 v가 나온 횟수
for _ in range(n):
    count[int(input())] += 1        # 수를 저장하지 않고 개수만 센다

for i in range(1, 10001):           # 작은 값부터
    if count[i]:
        line = str(i) + '\n'
        for _ in range(count[i]):   # 나온 횟수만큼 출력
            write(line)
```

- 최대 메모리 약 13MB (대부분 Python 자체가 쓰는 기본 메모리). 1,000만 개를 리스트에 담지 않으므로 N이 커져도 늘지 않는다.

## 해설

### 계수 정렬: 비교하지 않고 세기만 한다
- 투표함을 생각하면 쉽다. 1번부터 10,000번까지 **칸이 있는 상자**를 두고, 수가 하나 들어올 때마다 그 번호 칸에 표시 하나를 한다.
- 다 넣은 뒤 **1번 칸부터 순서대로** 표시 개수만큼 그 번호를 읽어 내면, 그게 정렬된 결과다.
- 두 수를 **한 번도 비교하지 않는다**. 그래서 비교 정렬의 한계인 O(N log N)보다 빠른 O(N + K)가 된다.

예제 `5 2 3 1 4 2 3 5 1 7`:

| 값 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| count | 2 | 2 | 2 | 1 | 2 | 0 | 1 |

→ 1 1 2 2 3 3 4 5 5 7

### 언제 쓸 수 있나
- 값이 **정수**이고 **범위가 작을 때**만 (여기선 10,000). 값이 10⁹까지면 배열이 너무 커져서 못 쓴다.
- 이 문제는 "N은 엄청 큰데 값의 범위는 작다"가 바로 그 신호다.

### 이 문제에서는 `join`으로 한 번에 출력하면 안 된다
- [오큰수](../../09-stack-queue/problems/next-greater.md)에서는 출력을 리스트에 모아 `'\n'.join`으로 한 번에 내보내는 게 빨랐다.
- 하지만 여기서는 출력이 1,000만 줄이다. 전부 하나의 문자열로 만들면 수십 MB가 되어 **메모리 제한을 넘는다.**
- 그래서 `sys.stdout.write`로 **한 줄씩** 내보낸다. `print`보다 가볍고, 출력은 내부 버퍼에 모였다가 나가서 메모리를 크게 쓰지 않는다.
- 정리: 출력이 많을 때 기본은 `join`, **메모리가 빠듯하면 `write`로 한 줄씩**.

### 수를 저장하지 않는 이유
- `a = [int(input()) for _ in range(n)]`처럼 1,000만 개를 리스트에 담으면 그것만으로 수십~수백 MB.
- 개수 배열은 N과 상관없이 칸 10,001개 → 아주 작다.

### 정렬 방법 정리 (지금까지 푼 것)

| 정렬 | 아이디어 | 시간 | 쓰는 상황 |
|---|---|---|---|
| 버블 / 선택 / 삽입 | 비교해서 바꾸기·고르기·끼우기 | O(N²) | N ≤ 수천, 정렬 과정 자체를 묻는 문제 |
| 퀵 (선택) | 피벗 기준으로 나누기 | 평균 O(N log N) (K번째만 O(N)) | K번째 수 |
| 병합 | 쪼개고 합치기 | O(N log N) | 뒤집힌 쌍 세기 |
| **계수** | **값마다 개수 세기** | **O(N + K)** | **값 범위가 작은 정수** |
| `sort()` | (내장, Timsort) | O(N log N) | 대부분의 실전 |

## 검증
- 예제 → `1 1 2 2 3 3 4 5 5 7`
- 값 1 ~ 10,000 무작위 1,000개에서 `count` → `a`로 고친 버전과 정답 풀이 모두 `sorted()`와 일치
- N = 10,000,000 → `input`/`print` 약 18.7초, `readline`/`write` 약 5.3초, 최대 메모리 둘 다 약 13MB (로컬)

## 배운 점
- **N은 큰데 값의 범위가 작은 정수** → 계수 정렬. 수를 저장하지 말고 값마다 개수만 센다.
- 메모리가 빠듯하면 출력을 `join`으로 모으지 말고 `sys.stdout.write`로 한 줄씩.
- 책 코드를 옮기다 변수 이름을 바꿨다면, **그 변수가 쓰인 모든 곳**을 함께 바꿨는지 확인한다.
