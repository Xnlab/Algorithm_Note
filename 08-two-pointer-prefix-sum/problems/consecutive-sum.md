# 연속된 자연수의 합 구하기 (백준 2018 수들의 합 5)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 투 포인터 / 백준 2018
- **유형**: 투 포인터
- **푼 날짜**: 2026-11-13
- **결과**: 정답 (책 풀이 방식) — 최대 입력에서 시간 주의

## 문제 요약
자연수 N(1 ≤ N ≤ 10,000,000)을 **연속된 자연수의 합**으로 나타내는 방법의 수를 구한다. N 자기 자신 하나만 쓰는 것도 한 가지 방법이다.
예: 15 = 1+2+3+4+5 = 4+5+6 = 7+8 = 15 → 4가지

## 떠올렸어야 할 단서
- "**연속된** 수의 합" + 모든 수가 양수 → 범위를 넓히면 합이 커지고, 좁히면 작아진다 → **투 포인터**
- N이 1,000만 → O(N²)은 불가능, O(N)이어야 한다
- 수열이 1, 2, 3, … 이라 배열을 따로 만들 필요 없이 포인터 값이 곧 수

## 내 풀이

```python
n = int(input())
start = 1
end = 1
count = 1
sum = 1

while end != n:
    if sum == n:
        count += 1
        end += 1
        sum += end
    elif sum > n:
        sum -= start
        start += 1
    else:
        end += 1
        sum += end

print(count)
```

- 시간복잡도: **O(N)** (start와 end가 각각 최대 N까지 한 방향으로만 움직임)
- 평가
  - 정답. 책 풀이와 같은 방식이다.
  - 세 가지 경우(같음 / 큼 / 작음)마다 포인터를 하나만 움직이는 투 포인터의 기본 틀이 정확하다.
  - 주의 1: 변수 이름 `sum`이 Python 내장 함수 `sum()`을 덮어쓴다. 이 코드에서는 `sum()`을 쓰지 않아 문제없지만, 같은 코드에서 `sum(리스트)`를 부르면 `TypeError`가 난다. `total`, `s` 같은 이름이 안전하다.
  - 주의 2: N = 10,000,000에서 로컬 실행 약 **2.5초**. 반복이 2,000만 번 가까이 돌아서, 백준에 Python 3로 내면 시간 초과가 날 수 있다. 같은 코드를 **PyPy3**로 제출하는 것이 일반적인 해결법이다.

## 해설

### 투 포인터의 뜻
- `start`, `end` 두 포인터가 **연속 구간 [start, end]**를 가리킨다. `sum`은 그 구간의 합 start + … + end.
- 두 포인터는 **오른쪽으로만** 움직인다. 그래서 각각 최대 N번, 합쳐 최대 2N번만 움직이고 O(N)이 된다.
- 모든 (start, end) 쌍을 확인하면 O(N²) = 최대 100조 번이지만, 투 포인터는 "어차피 답이 될 수 없는 쌍"을 건너뛴다.

### 세 가지 경우

| 상황 | 하는 일 | 이유 |
|---|---|---|
| `sum == n` | `count += 1`, end를 오른쪽으로 | 방법 하나 찾음. 이 start로 끝나는 다른 답은 없으니 다음 구간으로 |
| `sum > n` | 구간 맨 앞 수를 빼고 start를 오른쪽으로 | 합이 너무 큼 → 구간을 **왼쪽에서 줄임** |
| `sum < n` | end를 오른쪽으로, 새 수를 더함 | 합이 모자람 → 구간을 **오른쪽으로 늘림** |

- 포인터를 옮기는 순서가 중요하다.
  - **늘릴 때**: `end += 1` 먼저, 그다음 `sum += end` → 새로 들어온 수를 더함
  - **줄일 때**: `sum -= start` 먼저, 그다음 `start += 1` → 나가는 수를 뺌
  - 순서를 바꾸면 엉뚱한 수를 더하거나 뺀다.

### `count = 1`로 시작하는 이유
- 반복은 `end != n`일 동안만 돈다. end가 n에 닿는 순간 끝나므로, **N 자기 자신 하나로 이루어진 구간 [n, n]은 반복 안에서 세지 않는다.**
- 이 경우는 항상 답이 되니까 처음부터 1로 세어 두고 시작한다.
- 반복을 `end == n`에서 멈춰도 되는 이유: end가 n이면 구간에 n이 들어 있으므로, start < n인 이상 합은 n보다 크다. 남은 답은 [n, n] 하나뿐이고 그건 이미 셌다.

### 예제 따라가기 (N = 15)

| start | end | sum | 판단 | 동작 |
|---|---|---|---|---|
| 1 | 1 ~ 4 | 1, 3, 6, 10 | 작음 | end 늘리기 |
| 1 | 5 | 15 | **같음** | count = 2 (1+2+3+4+5), end 늘리기 |
| 1 | 6 | 21 | 큼 | 1 빼고 start = 2 |
| 2 | 6 | 20 | 큼 | 2 빼고 start = 3 |
| 3 | 6 | 18 | 큼 | 3 빼고 start = 4 |
| 4 | 6 | 15 | **같음** | count = 3 (4+5+6), end 늘리기 |
| 4 ~ 6 | 7 ~ 8 | … | 크거나 작음 | 줄이고 늘리기 반복 |
| 7 | 8 | 15 | **같음** | count = 4 (7+8), end 늘리기 |
| … | … | … | 큼 | start가 end를 쫓아가며 계속 줄임 |
| | 15 | | | end == 15 → 종료, 답 **4** (처음 센 15 포함) |

### 더 빠르게 풀 수도 있다 (참고)
- k개의 연속된 수 a, a+1, …, a+k−1의 합 = k·a + k(k−1)/2 = N
- → a = (N − k(k−1)/2) / k 가 **자연수**이면 방법 하나. k를 1부터 늘리며 N − k(k−1)/2 > 0인 동안만 확인하면 반복이 약 √(2N) ≈ 4,500번으로 줄어든다.
- 시험에서는 투 포인터로 푸는 게 정석이고, 시간이 걱정되면 PyPy3로 내는 것으로 충분하다.

## 검증
- 예제 N = 15 → `4`
- N = 1 ~ 1,500 전부에서 모든 시작점을 직접 더해 센 결과와 일치
- N = 10,000,000 → `8`, N = 9,999,991 → `2`, 각각 로컬 약 2.5초

## 배운 점
- **연속 구간 + 모든 값이 양수** → 투 포인터. 합이 작으면 end를, 크면 start를 오른쪽으로.
- 늘릴 땐 "옮기고 더하기", 줄일 땐 "빼고 옮기기" 순서를 지킨다.
- 반복 조건 밖에서 처리되는 경우(여기선 N 자신)는 초기값으로 미리 센다.
- 내장 함수 이름(`sum`, `max`, `min`, `list`, `input`)은 변수 이름으로 쓰지 않는다.
