# 주몽의 명령 (백준 1940 주몽)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 투 포인터 / 백준 1940
- **유형**: 투 포인터 (정렬 + 양 끝에서 좁히기)
- **푼 날짜**: 2026-11-13
- **결과**: 정답

## 문제 요약
서로 다른 고유 번호를 가진 재료 N개(N ≤ 15,000) 중 두 개를 골라 번호의 합이 M이 되는 쌍의 개수를 구한다. 한 재료는 한 번만 쓸 수 있다.

## 떠올렸어야 할 단서
- "**두 수의 합**이 M인 쌍의 개수" → 정렬 후 **양 끝 투 포인터**
- 정렬하면 "합이 크면 큰 쪽을 줄이고, 작으면 작은 쪽을 키운다"가 성립
- N = 15,000 → 모든 쌍 확인 O(N²) ≈ 1억 1천만 → Python으로는 위험. 정렬 O(N log N) + 투 포인터 O(N)

## 내 풀이

```python
n = int(input())
m = int(input())
data = list(map(int, input().split()))
data.sort()
count = 0
start = data[0]
end = data[n-1]
index_s = 0
index_e = n-1

while start < end:
    if start + end == m:
        count += 1
        index_s += 1
        index_e -= 1
        start = data[index_s]
        end = data[index_e]
    elif start + end > m:
        index_e -= 1
        end = data[index_e]
    else:
        index_s += 1
        start = data[index_s]

print(count)
```

- 시간복잡도: **O(N log N)** (정렬이 지배, 투 포인터는 O(N))
- 평가
  - 정답. 정렬 → 양 끝에서 시작 → 합에 따라 한쪽씩 좁히기의 흐름이 정확하다.
  - 포인터 위치(`index_s`, `index_e`)와 그 위치의 값(`start`, `end`)을 **따로** 들고 다녀서 코드가 길어졌다. 포인터를 옮길 때마다 값도 다시 읽어야 하니 줄이 두 배가 된다.
  - 반복 조건 `start < end`는 **값**을 비교한다. 문제에서 번호가 **서로 다르다**고 보장했기 때문에 "값이 작다 ⇔ 위치가 앞이다"가 성립해서 맞게 동작한다. 같은 번호가 있을 수 있는 문제였다면 `[3, 3]`, M = 6에서 답 1을 못 세고 0이 나온다.

## 정답 풀이 (책 풀이 방식)

값을 따로 저장하지 않고 **인덱스만** 움직이며 필요할 때 `A[i]`, `A[j]`로 읽는 형태.

```python
n = int(input())
m = int(input())
A = list(map(int, input().split()))
A.sort()
count = 0
i = 0               # 왼쪽 포인터 (작은 수)
j = n - 1           # 오른쪽 포인터 (큰 수)

while i < j:        # 위치를 비교 → 같은 재료를 두 번 쓰지 않음
    if A[i] + A[j] < m:
        i += 1      # 합이 작음 → 작은 쪽을 키움
    elif A[i] + A[j] > m:
        j -= 1      # 합이 큼 → 큰 쪽을 줄임
    else:
        count += 1  # 찾음 → 두 재료 모두 사용, 양쪽 다 이동
        i += 1
        j -= 1

print(count)
```

- 내 풀이와 결과는 같다 (서로 다른 번호의 무작위 입력 5,000개에서 일치).
- 차이: 값을 담는 변수 `start`, `end`가 없어 포인터 이동이 한 줄씩이고, 반복 조건이 **위치 비교**라 중복 값이 있어도 안전하다.

## 해설

### 왜 정렬하면 양 끝에서 좁힐 수 있는가
정렬된 배열에서 `A[i] + A[j]`를 보면:
- **합 > M**: A[j]는 지금의 A[i](남은 것 중 가장 작은 수)와 더해도 크다. 그러면 더 큰 A[i]들과는 당연히 더 크다. → **A[j]는 어떤 짝으로도 답이 될 수 없으니 버린다** (`j -= 1`)
- **합 < M**: A[i]는 지금의 A[j](남은 것 중 가장 큰 수)와 더해도 작다. → **A[i]도 답이 될 수 없으니 버린다** (`i += 1`)
- **합 == M**: 찾았다. 재료는 한 번만 쓸 수 있으니 둘 다 버린다.

매 단계에서 답이 될 수 없는 수를 하나 이상 확실히 지우므로, 포인터는 최대 N번 움직이고 O(N)이 된다.

### 연속된 자연수의 합과 비교
| | 연속된 자연수의 합 | 주몽 |
|---|---|---|
| 포인터 시작 | 둘 다 왼쪽 | **양 끝** |
| 움직이는 방향 | 둘 다 오른쪽 | 서로를 향해 |
| 다루는 것 | 연속 **구간**의 합 | **두 수**의 합 |
| 정렬 | 필요 없음 (1, 2, 3, …) | **필수** |
| 종료 | end가 N에 닿을 때 | 두 포인터가 만날 때 |

### 값 비교 `start < end` vs 위치 비교 `i < j`
- 반복을 멈춰야 하는 순간은 **두 포인터가 같은 재료를 가리키거나 엇갈릴 때**다. 그건 위치의 문제다.
- 번호가 모두 다르면 정렬 후 값의 크기 순서 = 위치 순서라서 값 비교도 맞다.
- 같은 값이 있으면 위치는 다른데 값이 같은 경우가 생긴다. `[3, 3]`, M = 6:
  - 값 비교: `3 < 3`이 거짓 → 반복을 한 번도 안 돌고 **0**
  - 위치 비교: `0 < 1`이 참 → 3 + 3 = 6을 찾아 **1**
- 투 포인터의 종료 조건은 **위치(인덱스)로 쓰는 습관**을 들이면 문제 조건이 바뀌어도 안전하다.

### 예제 따라가기 (N = 6, M = 9, 재료 2 7 4 1 5 3)
정렬 → `1 2 3 4 5 7`

| i | j | A[i] + A[j] | 판단 | 동작 |
|---|---|---|---|---|
| 0 (1) | 5 (7) | 8 | 작음 | i 이동 |
| 1 (2) | 5 (7) | **9** | 같음 | count = 1 (2+7), 둘 다 이동 |
| 2 (3) | 4 (5) | 8 | 작음 | i 이동 |
| 3 (4) | 4 (5) | **9** | 같음 | count = 2 (4+5), 둘 다 이동 |
| 4 | 3 | | i ≥ j | 종료, 답 **2** |

## 검증
- 예제 → `2`
- 1 ≤ N ≤ 20, 서로 다른 번호의 무작위 입력 5,000개에서 내 풀이·정답 풀이 모두 모든 쌍을 직접 센 결과와 일치
- N = 1 → `0` (오류 없음)
- 중복 값 `[3, 3]`, M = 6 → 내 풀이 0, 정답 풀이 1 (문제 조건상 나오지 않는 입력)
- N = 15,000 → 두 풀이 모두 로컬 0.1초 미만

## 배운 점
- **두 수의 합 = M인 쌍** → 정렬 + 양 끝 투 포인터. 크면 오른쪽을 줄이고, 작으면 왼쪽을 키운다.
- 포인터는 **인덱스만** 들고 다니고 값은 필요할 때 `A[i]`로 읽는다. 값을 따로 저장하면 이동할 때마다 갱신할 줄이 늘어난다.
- 투 포인터의 종료 조건은 값이 아니라 **위치**로 비교한다.
