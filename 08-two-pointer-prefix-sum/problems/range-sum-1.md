# 구간 합 구하기 1 (백준 11659 구간 합 구하기 4)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 구간 합 / 백준 11659
- **유형**: 누적합 (구간 합)
- **푼 날짜**: 2026-11-10
- **결과**: 정답 (논리) — 백준 제출 시 빠른 입력 권장

## 문제 요약
수 N개(N ≤ 100,000)가 주어지고, 구간 [i, j]의 합을 묻는 질의가 M개(M ≤ 100,000) 들어올 때 각 질의의 답을 출력한다.

## 떠올렸어야 할 단서
- **같은 배열에 구간 합 질의가 여러 번** → 매번 더하면 O(N × M) = 최대 100억 → 불가능
- 배열이 바뀌지 않음 → 합을 **미리 한 번** 구해 두고 질의마다 O(1)로 답한다 → **누적합**
- 입력이 최대 20만 줄 → `sys.stdin.readline`

## 내 풀이

```python
n, qu = map(int, input().split())
numbers = map(int, input().split())
prefix_sum = [0]
temp = 0

for i in numbers:
    temp += i
    prefix_sum.append(temp)

for _ in range(qu):
    s, e = map(int, input().split())
    print(prefix_sum[e] - prefix_sum[s-1])
```

- 시간복잡도: **O(N + M)** (누적합 만들기 O(N), 질의마다 O(1))
- 평가
  - 정답. 누적합 배열을 만들고 `S[j] - S[i-1]`로 답하는 공식이 정확하다.
  - `prefix_sum = [0]`으로 **맨 앞에 0을 두어** 1번부터 시작하는 문제 번호와 인덱스를 맞춘 것이 잘한 점. 덕분에 `s = 1`일 때도 `prefix_sum[0] = 0`을 빼게 되어 별도 처리가 필요 없다.
  - 주의: 입력이 최대 20만 줄, 출력이 10만 줄이라 `input()`과 `print()`를 그대로 쓰면 **백준 Python 채점에서 시간 초과가 날 수 있다.** 맨 위에 `input = sys.stdin.readline`을 넣는 것이 안전하다.

## 정답 풀이 (책 풀이 방식)

내 풀이에 빠른 입력만 추가한 코드.

```python
import sys
input = sys.stdin.readline                  # 입력이 많으므로 빠른 입력

n, qu = map(int, input().split())           # 수의 개수, 질의 개수
numbers = map(int, input().split())         # 구간 합을 구할 수들

prefix_sum = [0]                            # S[0] = 0 (1번부터 시작하도록)
temp = 0
for i in numbers:
    temp += i
    prefix_sum.append(temp)                 # S[k] = 1번 ~ k번 수의 합

for _ in range(qu):
    s, e = map(int, input().split())
    print(prefix_sum[e] - prefix_sum[s-1])  # 구간 합 = S[e] - S[s-1]
```

## 해설

### 매번 더하면 왜 안 되는가
- 질의 하나에 최대 N개를 더하면 O(N), 질의가 M개면 **O(N × M)**.
- N, M이 각각 10만이면 최대 **100억 번** → Python으로 1초 안에 불가능 (1초 ≈ 1,000만~2,000만 연산).
- 그런데 배열 자체는 바뀌지 않는다. 같은 덧셈을 질의마다 반복하고 있는 셈이다.

### 누적합의 정의
`S[k]` = 1번째 수부터 k번째 수까지의 합, `S[0] = 0`

예제 `5 4 3 2 1`:

| k | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| A[k] | | 5 | 4 | 3 | 2 | 1 |
| S[k] | **0** | 5 | 9 | 12 | 14 | 15 |

- 만드는 법: `S[k] = S[k-1] + A[k]`. 코드에서는 `temp`가 지금까지의 합을 들고 다니며 하나씩 더해 `append`한다.

### 구간 합 공식 `S[j] - S[i-1]`
- `S[j]` = 1번 ~ j번의 합
- `S[i-1]` = 1번 ~ (i−1)번의 합
- 빼면 앞부분이 지워져서 **i번 ~ j번의 합**만 남는다.

예제 질의 `2 4` (4 + 3 + 2 = 9):
```
S[4] = 5 + 4 + 3 + 2 = 14
S[1] = 5               =  5
S[4] - S[1]   = 4 + 3 + 2 =  9
```

| 질의 | 계산 | 답 |
|---|---|---|
| 1 3 | S[3] − S[0] = 12 − 0 | 12 |
| 2 4 | S[4] − S[1] = 14 − 5 | 9 |
| 5 5 | S[5] − S[4] = 15 − 14 | 1 |

### 맨 앞에 0을 두는 이유
- 0이 없으면 `S[0]`이 첫 번째 수가 되어 인덱스가 하나씩 밀린다. 그러면 `i = 1`인 질의에서 `S[i-1] = S[0]`을 빼면 첫 번째 수가 빠져 버리고, 0-index로 바꾸면 `S[-1]`이 되어 **리스트의 마지막 값**을 빼는 버그가 생긴다.
- 크기 N+1, `S[0] = 0`으로 두면 공식 하나로 모든 질의가 처리된다. ([08 README](../README.md)의 "자주 하는 실수"와 같은 내용)

### 빠른 입력이 필요한 이유
- `input()`은 한 줄을 읽을 때마다 부가 처리가 많아 느리다. 이 문제는 최대 **20만 줄 이상**을 읽는다.
- `sys.stdin.readline`은 훨씬 가볍다. 끝에 줄바꿈 문자가 남지만 `split()`과 `int()`가 처리해 주므로 이 문제에선 그대로 써도 된다.
- 출력도 10만 줄이라, 더 줄이고 싶으면 답을 리스트에 모아 마지막에 한 번 출력한다.
  ```python
  answers = []
  for _ in range(qu):
      s, e = map(int, input().split())
      answers.append(prefix_sum[e] - prefix_sum[s-1])
  print('\n'.join(map(str, answers)))
  ```

## 검증
- 예제 `5 3 / 5 4 3 2 1 / 1 3, 2 4, 5 5` → `12 9 1`
- 1 ≤ N, M ≤ 30, 무작위 2,000개 입력에서 질의마다 직접 더한 값과 일치
- N = M = 100,000 입력: 내 풀이와 정답 풀이의 출력 동일. 로컬에서는 둘 다 0.5초 이내였지만, 채점 서버는 입력 방식에 따라 차이가 더 크게 날 수 있어 빠른 입력을 기본으로 쓴다.

## 배운 점
- **같은 배열에 구간 합 질의가 많으면 누적합.** 미리 O(N)으로 만들고, 질의마다 `S[j] - S[i-1]`로 O(1).
- 누적합 배열은 **크기 N+1, 맨 앞 0**으로 만든다.
- 입력이 10만 줄 이상이면 `input = sys.stdin.readline`을 습관처럼 넣는다.
