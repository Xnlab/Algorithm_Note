# 나머지 합 구하기 (백준 10986 나머지 합)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 구간 합 / 백준 10986
- **유형**: 누적합 + 나머지 + 조합
- **푼 날짜**: 2026-11-12
- **결과**: 정답 (책 풀이 방식)

## 문제 요약
수 N개(N ≤ 1,000,000)가 주어질 때, 연속된 구간의 합이 M(M ≤ 1,000)으로 나누어떨어지는 구간 (i, j) 쌍의 개수를 구한다.

## 떠올렸어야 할 단서
- "연속된 구간의 합" → **누적합** (구간 합 = `S[j] - S[i-1]`)
- "M으로 나누어떨어지는" → 구간 합의 **나머지가 0** → `S[j] % M == S[i-1] % M`
- N이 100만 → 모든 (i, j) 쌍 확인은 O(N²) = 1조 → 불가능. **같은 나머지끼리 개수만 세서 조합으로 계산**
- M ≤ 1,000 → 나머지별 개수를 담을 배열 `C`의 크기가 작다

## 내 풀이

```python
n, m = map(int, input().split())
A = list(map(int, input().split()))
S = [0] * n
C = [0] * m
S[0] = A[0]
answer = 0

for i in range(1, n):
    S[i] = S[i-1] + A[i]

for i in range(n):
    remainder = S[i] % m
    if remainder == 0:
        answer += 1
    C[remainder] += 1

for i in range(m):
    if C[i] > 1:
        answer += C[i] * (C[i]-1) // 2

print(answer)
```

- 시간복잡도: **O(N + M)**
- 평가
  - 정답. 책 풀이와 같은 방식이다.
  - 누적합 → 나머지 → 같은 나머지끼리 조합의 세 단계가 정확하다.
  - `S`와 `C`는 `S[i] = ...`, `C[r] += 1`처럼 **자리를 지정해서** 채우므로 미리 크기를 만든 것이 맞다 ([구간 합 2](range-sum-2.md)에서 정리한 기준).
  - `// 2`로 정수 나눗셈을 써서 답이 실수(`3.0`)로 출력되는 실수를 피했다.

## 해설

### 1단계: 구간 합 문제를 나머지 문제로 바꾸기
- 구간 i ~ j의 합 = `S[j] - S[i-1]`
- 이게 M으로 나누어떨어진다 ⇔ `(S[j] - S[i-1]) % M == 0`
- ⇔ **`S[j] % M == S[i-1] % M`** (두 수의 차가 M의 배수 ⇔ 두 수를 M으로 나눈 나머지가 같다)
- 예: M = 3, 7과 13 → 차 6은 3의 배수, 7 % 3 = 1, 13 % 3 = 1 → 나머지가 같다.

즉, 문제가 **"누적합의 나머지가 같은 두 위치를 고르는 경우의 수"**로 바뀐다. 실제 구간 합을 하나도 계산하지 않아도 된다.

### 2단계: 나머지별 개수 세기 `C[remainder] += 1`
- `C[r]` = 누적합의 나머지가 r인 위치의 개수
- 나머지는 0 ~ M−1 중 하나이므로 `C`의 크기는 M.

### 3단계: 같은 나머지끼리 두 개 고르기 `C[i] * (C[i]-1) // 2`
- 나머지가 같은 위치가 k개 있으면, 그중 **두 개를 고르는 방법**마다 조건을 만족하는 구간이 하나씩 생긴다.
- k개 중 2개를 고르는 경우의 수 = **kC2 = k × (k − 1) / 2**
  - 첫 번째 고르기 k가지 × 두 번째 고르기 (k − 1)가지, 순서가 상관없으니 ÷ 2
- `if C[i] > 1`: 하나 이하면 두 개를 고를 수 없어서 0. 사실 k = 0, 1이면 공식도 0이 나오므로 이 if는 없어도 결과는 같다.

### `if remainder == 0: answer += 1`은 왜 필요한가
- 3단계는 **두 위치를 골라** `S[j] - S[i-1]`로 만드는 구간만 센다. 그런데 **1번부터 시작하는 구간**(i = 1)은 `S[j] - S[0]`이 아니라 `S[j]` 자체가 구간 합이다.
- 그래서 `S[j]` 혼자 나머지가 0이면, 1번 ~ j번 구간 하나가 조건을 만족한다 → 따로 1을 더한다.
- 다른 시각으로 보면: 누적합 맨 앞에 **S = 0인 위치(0번)가 하나 더 있다**고 생각하는 것과 같다. 0의 나머지는 0이므로, 나머지가 0인 위치와 짝지을 상대가 하나 더 생기는 셈이다.
  - [구간 합 1](range-sum-1.md)처럼 `S = [0]`으로 시작해 0을 깔아 두면 `C[0]`이 처음부터 1이 되어, 이 `if` 없이 조합 공식 하나로 같은 답이 나온다.

### 예제 따라가기 (N = 5, M = 3, A = 1 2 3 1 2)

| 위치 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| A | 1 | 2 | 3 | 1 | 2 |
| S | 1 | 3 | 6 | 7 | 9 |
| S % 3 | 1 | **0** | **0** | 1 | **0** |

- `C = [3, 2, 0]` (나머지 0이 3개, 1이 2개, 2가 0개)

| 계산 | 개수 | 해당 구간 |
|---|---|---|
| 나머지 0인 위치 각각 (1번부터 시작하는 구간) | 3 | [1~2] 3, [1~3] 6, [1~5] 9 |
| C[0] = 3 → 3C2 | 3 | 위치 2·3 → [3~3] 3, 위치 2·5 → [3~5] 6, 위치 3·5 → [4~5] 3 |
| C[1] = 2 → 2C2 | 1 | 위치 1·4 → [2~4] 6 |
| **합계** | **7** | |

- 위치 i와 j를 골랐을 때 구간은 **(i + 1) ~ j**다. `S[j] - S[i]`에서 앞쪽 S[i]에 포함된 부분이 빠지기 때문.

### 큰 수 처리
- A의 값이 최대 10⁹, N이 100만이라 누적합은 최대 10¹⁵까지 커진다. Python 정수는 크기 제한이 없어 문제없다.
- 다른 언어(C++, Java)에서는 `long long`/`long`을 쓰거나, 누적할 때부터 `% M`을 해서 값을 작게 유지한다. Python에서도 `S[i] = (S[i-1] + A[i]) % m`으로 저장하면 같은 답이 나온다.

## 검증
- 예제 `5 3 / 1 2 3 1 2` → `7`
- 1 ≤ N ≤ 25, 2 ≤ M ≤ 12 무작위 3,000개 입력에서 모든 구간을 직접 더해 센 결과와 일치
- N = 1,000,000, M = 1,000 → 로컬 약 0.5초

## 배운 점
- **"구간 합이 M의 배수"** → 누적합의 나머지가 같은 두 위치 → **같은 나머지끼리 kC2.**
- 쌍(pair)의 개수를 세는 문제는 쌍을 직접 만들지 말고, **같은 그룹의 개수 k를 센 뒤 k(k−1)/2**로 계산한다.
- 1번부터 시작하는 구간을 따로 세는 `if`는, 누적합 맨 앞의 0을 하나의 위치로 보는 것과 같다.
