# 절댓값 힙 구현하기 (백준 11286 절댓값 힙)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 스택과 큐 / 백준 11286
- **유형**: 우선순위 큐 (힙)
- **푼 날짜**: 2026-11-19
- **결과**: 오답 (값은 맞지만 출력에 빈 줄이 섞임)

## 문제 요약
연산 N개(N ≤ 100,000)가 주어진다. 0이 아닌 x는 배열에 넣고, 0이면 배열에서 **절댓값이 가장 작은 값**을 출력하고 지운다. 절댓값이 같으면 **더 작은 값(음수)**을 먼저 꺼낸다. 비어 있으면 0을 출력한다.

## 떠올렸어야 할 단서
- "가장 작은 것을 **계속** 꺼내기" + 중간중간 새 값이 들어옴 → **우선순위 큐(힙)**. 넣기·꺼내기 각 O(log N)
- 매번 정렬하거나 `min()`으로 찾으면 꺼낼 때마다 O(N) → 최대 100억 번 → 불가능
- 우선순위가 두 단계(절댓값 → 실제 값) → 힙에 **튜플 `(절댓값, 값)`**을 넣으면 자동으로 그 순서대로 비교

## 내 풀이

```python
from queue import PriorityQueue
n = int(input())
queue = PriorityQueue()

for i in range(n):
    request = int(input())
    if request == 0:
        if queue.empty():
            print('0', end='\n')
        else:
            temp = queue.get()
            print(str((temp[1]))+'\n')
    else:
        queue.put((abs(request), request))
```

- 시간복잡도: **O(N log N)**
- 평가
  - 꺼내는 **값의 순서는 정확하다.** 튜플 `(abs(request), request)`로 넣어 절댓값이 같을 때 음수가 먼저 나오게 한 것이 이 문제의 핵심이고, 그걸 바로 짚었다.
  - **버그 1개**: `print(str(temp[1]) + '\n')` → `print`는 끝에 이미 줄바꿈을 붙이므로 `'\n'`이 하나 더 붙어 **값마다 빈 줄**이 생긴다.
    ```
    -1
    (빈 줄)
    1
    (빈 줄)
    0        ← 0 출력은 print('0', end='\n')이라 빈 줄 없음
    ```
  - 무작위 2,000개 입력에서 값 순서는 모두 맞았지만, "한 줄에 하나씩" 기준으로는 1,395개가 달랐다. 채점에서 출력 형식 오류나 오답으로 처리될 수 있다.

## 정답 풀이 (책 풀이 방식)

내 풀이의 구조 그대로, 빈 줄 버그를 고치고 `heapq`·빠른 입력·한 번 출력을 적용한 코드.

```python
import sys
import heapq
input = sys.stdin.readline

n = int(input())
heap = []
out = []

for _ in range(n):
    request = int(input())
    if request == 0:
        if heap:
            out.append(heapq.heappop(heap)[1])   # (절댓값, 값) 중 값만
        else:
            out.append(0)
    else:
        heapq.heappush(heap, (abs(request), request))

print('\n'.join(map(str, out)))
```

- N = 100,000에서 로컬 약 0.06초 (내 풀이 약 0.17초).

## 해설

### 힙이 하는 일
- 힙은 **가장 작은 값을 맨 앞에** 두는 자료구조다. 넣기와 꺼내기가 각각 O(log N).
- 전체를 정렬된 상태로 유지하지는 않는다. "맨 앞이 가장 작다"만 보장해서 빠르다.
- Python에서 힙을 쓰는 방법은 두 가지다.

| | `heapq` | `queue.PriorityQueue` |
|---|---|---|
| 형태 | 리스트 + 함수 (`heappush`, `heappop`) | 클래스 (`put`, `get`) |
| 비었나 | `if heap:` / `if not heap:` | `queue.empty()` |
| 속도 | **빠름** | 여러 스레드에서 안전하게 쓰도록 잠금 처리가 있어 느림 |
| 코테 | **주로 사용** | 결과는 같지만 굳이 쓸 이유가 없음 |

### 튜플로 두 단계 우선순위 만들기
- 튜플은 **첫 번째 값부터** 비교하고, 같으면 두 번째 값을 비교한다.
- `(abs(x), x)`를 넣으면:
  1. 절댓값이 작은 것이 먼저
  2. 절댓값이 같으면 실제 값이 작은 것(음수)이 먼저
- 예: `-1`, `1`, `-2`, `2` → `(1, -1)`, `(1, 1)`, `(2, -2)`, `(2, 2)` 순서로 나온다.
- [정렬의 `key=lambda s: (s[1], s[0])`](../../04-sort-binary-search/problems/low-score-order.md)와 같은 원리다. 정렬은 key 함수로, 힙은 튜플을 직접 넣어서 기준을 정한다.

### `print`의 줄바꿈
- `print(x)`는 `x`를 출력한 뒤 **자동으로 `\n`을 붙인다** (`end='\n'`이 기본값).
- 그래서 `print(x + '\n')`은 줄바꿈이 두 번 → 빈 줄이 생긴다.
- `print('0', end='\n')`은 기본값을 다시 적은 것이라 `print('0')`과 같다.
- 출력이 많을 땐 결과를 리스트에 모아 `'\n'.join(...)`으로 한 번에 출력한다 ([오큰수](next-greater.md)에서 본 것과 같은 방식).

### 예제 따라가기 (앞부분)

| 입력 | 동작 | 힙 (절댓값, 값) | 출력 |
|---|---|---|---|
| 1 | 넣기 | (1, 1) | |
| −1 | 넣기 | (1, −1) (1, 1) | |
| 0 | 꺼내기 | (1, 1) | −1 |
| 0 | 꺼내기 | (빈) | 1 |
| 0 | 꺼내기 | (빈) | 0 |

## 검증
- 예제 (18개 연산) → `-1 1 0 -1 -1 1 1 -2 2 0` (내 풀이는 값은 같지만 빈 줄이 섞임)
- 연산 1 ~ 30개 무작위 2,000개: 정답 풀이는 값·줄 형식 모두 일치. 내 풀이는 값 순서 일치, 줄 형식 1,395개 불일치
- N = 100,000 → 정답 풀이 약 0.06초, 내 풀이 약 0.17초

## 배운 점
- **"가장 작은(큰) 것을 계속 꺼내기 + 중간에 계속 넣기"** → 힙. 코테에서는 `heapq`.
- 우선순위가 여러 단계면 **튜플** `(1순위, 2순위, …)`로 넣는다.
- `print`는 끝에 줄바꿈을 자동으로 붙인다. 출력 문자열에 `'\n'`을 직접 붙이지 않는다.
