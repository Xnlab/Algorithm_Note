# 오큰수 구하기 (백준 17298 오큰수)

- **출처**: Do it! 알고리즘 코딩테스트 with 파이썬 — 스택과 큐 / 백준 17298
- **유형**: 단조 스택
- **푼 날짜**: 2026-11-18
- **결과**: 정답 (논리) — 출력 방식 때문에 최대 입력에서 느림

## 문제 요약
수열 A(N ≤ 1,000,000)의 각 원소마다, **오른쪽에 있으면서 그 원소보다 큰 수 중 가장 왼쪽에 있는 수**(오큰수)를 구한다. 없으면 −1.
예: `3 5 2 7` → `5 7 7 -1`

## 떠올렸어야 할 단서
- "오른쪽에서 **처음** 나오는 더 큰 수" → **단조 스택**
- N이 100만 → 원소마다 오른쪽을 훑으면 O(N²) = 1조 → 불가능, O(N)이어야 한다
- 답을 **원소의 위치**에 적어야 함 → 스택에 값이 아니라 **인덱스**를 넣는다

## 내 풀이

```python
n = int(input())
ans = [0] * n
a = list(map(int, input().split()))
stack = []

for i in range(n):
    while stack and a[stack[-1]] < a[i]:
        ans[stack.pop()] = a[i]
    stack.append(i)
while stack:
    ans[stack.pop()] = -1

for i in range(n):
    print(ans[i], end= ' ')
```

- 시간복잡도: **O(N)** (각 인덱스는 한 번 push, 한 번 pop)
- 평가
  - 정답. 책 풀이와 같은 방식이다. 예제 두 개와 중복 값이 섞인 무작위 3,000개에서 모두 일치.
  - 스택에 **인덱스**를 넣고 `a[stack[-1]]`로 값을 비교한 것, `while stack and ...`으로 빈 스택을 먼저 확인한 것이 정확하다.
  - 주의: 마지막 출력에서 `print`를 **100만 번** 부른다. N = 1,000,000에서 로컬 약 **1.3초**가 걸렸고, 대부분이 출력 시간이다. 백준 Python 제출에서는 시간 초과가 날 수 있다.

## 정답 풀이 (책 풀이 방식)

내 풀이에서 출력만 한 번에 하도록 바꾼 코드.

```python
n = int(input())
ans = [0] * n
a = list(map(int, input().split()))
stack = []                              # 아직 오큰수를 못 찾은 원소의 인덱스

for i in range(n):
    # 지금 수 a[i]가 스택 맨 위 원소보다 크면 → 그 원소의 오큰수는 a[i]
    while stack and a[stack[-1]] < a[i]:
        ans[stack.pop()] = a[i]
    stack.append(i)                     # a[i]도 오큰수를 기다리는 줄에 선다

while stack:                            # 끝까지 큰 수를 못 만난 원소들
    ans[stack.pop()] = -1

print(' '.join(map(str, ans)))          # 한 번에 출력
```

- 같은 입력에서 약 **0.4초** (출력 100만 번 → 1번).

## 해설

### 스택에 남아 있는 것 = "아직 오큰수를 못 찾은 원소"
- 왼쪽부터 하나씩 보면서, 각 원소를 일단 스택에 넣어 **기다리게** 한다.
- 새 수 a[i]가 들어올 때, 스택에서 기다리던 원소들 중 a[i]보다 작은 것들은 **a[i]가 바로 그들의 오큰수**다. 그래서 꺼내면서 답을 적는다.
- a[i]보다 크거나 같은 원소를 만나면 멈춘다. 그 아래에 있는 원소들은 더 크거나 같으므로 볼 필요가 없다.

### 스택은 왜 항상 "위로 갈수록 작거나 같은" 상태인가 (단조 스택)
- 넣기 직전에 a[i]보다 작은 것을 모두 꺼냈으니, a[i]를 넣으면 a[i]는 바로 아래 원소보다 **작거나 같다.**
- 그래서 맨 위만 확인하면 된다. 맨 위가 a[i]보다 크거나 같으면, 그 아래는 모두 더 크거나 같아서 a[i]가 오큰수가 될 수 없다.
- 같은 값은 "더 큰 수"가 아니므로 `<`로 비교해 꺼내지 않는다 (`<=`로 쓰면 같은 값을 오큰수로 잘못 적는다).

### 왜 O(N)인가
- `for` 안에 `while`이 있어 O(N²)처럼 보이지만, 각 인덱스는 스택에 **한 번 들어가고 한 번 나온다.** `while`이 전체를 통틀어 도는 횟수는 최대 N번이다.
- 그래서 전체 연산은 push N번 + pop N번 = O(N).

### 왜 인덱스를 넣는가
- 답은 "i번째 원소의 오큰수"처럼 **위치**에 적어야 한다. 값만 넣으면 꺼냈을 때 그 값이 몇 번째 원소였는지 알 수 없다 (같은 값이 여러 개일 수도 있다).
- 인덱스를 넣으면 값은 `a[인덱스]`로 언제든 읽을 수 있다. ([주몽의 명령](../../08-two-pointer-prefix-sum/problems/jumong.md)에서 "포인터는 위치, 값은 꺼내 보는 정보"와 같은 원리)

### 마지막 `while stack`
- 끝까지 남은 원소들은 오른쪽에 더 큰 수가 없었다 → −1.
- `ans = [-1] * n`으로 처음부터 −1을 채워 두면 이 반복은 없어도 된다.

### 예제 따라가기 (`3 5 2 7`)

| i | a[i] | 꺼낸 것 (답 기록) | 스택 (인덱스: 값) |
|---|---|---|---|
| 0 | 3 | — | [0:3] |
| 1 | 5 | 0 → ans[0] = 5 | [1:5] |
| 2 | 2 | — (5 > 2) | [1:5, 2:2] |
| 3 | 7 | 2 → ans[2] = 7, 1 → ans[1] = 7 | [3:7] |
| 끝 | | 3 → ans[3] = −1 | [] |

→ `5 7 7 -1`

### 출력이 많을 때
- `print`는 부를 때마다 처리 비용이 있다. 100만 번 부르면 그것만으로 1초 가까이 걸린다.
- 답을 리스트에 모아 `' '.join(map(str, ans))`로 **한 번에** 출력한다. `join`은 문자열끼리만 이을 수 있어서 `map(str, ...)`로 숫자를 문자열로 바꾼다.

## 검증
- 예제 `3 5 2 7` → `5 7 7 -1`, `9 5 4 8` → `-1 8 8 -1`
- 길이 1 ~ 20, 값 1 ~ 10(중복 포함) 무작위 3,000개에서 오른쪽을 직접 훑은 결과와 일치
- N = 1,000,000 (무작위 / 내림차순): 내 풀이 약 1.3초, 정답 풀이 약 0.4초, 두 출력 내용 동일

## 배운 점
- **"오른쪽(왼쪽)에서 처음 나오는 더 큰(작은) 값"** → 단조 스택. 스택에는 "아직 답을 못 찾은 것"의 **인덱스**를 둔다.
- `for` 안의 `while`이라도 각 원소가 한 번씩만 들어가고 나오면 전체 O(N).
- 출력이 수십만 줄 이상이면 `print` 반복 대신 `join`으로 한 번에.
